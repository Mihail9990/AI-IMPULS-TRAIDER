# Проверка подключения на Windows VPS без торговых команд

`run_recovery_diagnostics.py` — однократная диагностика, а не торговый сервис.
Она проверяет соединение с конкретным MT5, ожидаемый счёт/сервер, hedging,
доступность символа, котировки и истории. Вывод содержит флаги и количества,
но не баланс, номер счёта, тикеты, пароли или подробности сделок.

## Перед запуском

- Установить Windows MT5 и совместимый Python с официальным пакетом MetaTrader5.
  Этот проект автоматически их не устанавливает и параметры терминала не меняет.
- Войти в нужный счёт вручную; подготовить точные account/server/symbol.
- Убедиться, что выбран правильный `terminal64.exe`.
- Проверить работающие в терминале советники: `initialize` может запустить сам
  терминал и уже настроенные в нём EA. Диагностический скрипт торговых команд не
  отправляет, но не управляет другими советниками и не останавливает их.

Из каталога `server` выполнить вручную, заменив параметры:

```powershell
python .\run_recovery_diagnostics.py --connect-read-only --terminal "C:\Path\MetaTrader 5\terminal64.exe" --account 123456 --server "ExactBrokerServer" --symbol "XAUUSD.s"
```

Не вводить пароль в команду. Скрипт использует текущий сохранённый терминалом
счёт и проверяет совпадение; аккаунт не переключает. `--history-days` допускает
1–30, по умолчанию 1. Нет `order_send`, `order_check`, `login`, `symbol_select`,
изменения SL/TP или включения алгоритмической торговли. После проверки соединение
Python закрывается через `shutdown`; сам терминал может оставаться открытым.

Код возврата 0 означает только успешное чтение. `safe_to_trade` всегда false.
Код 1 — ошибка подключения/чтения, 2 — ошибка параметров/среды. Ошибка намеренно
не печатает сырые API-объекты; для поиска причины проверять терминал локально.

Пока выполнены только fake-API тесты. Windows/MT5 и MQL5-компиляция не проверены.
Рабочий native RECOVERY runner, доверенный EA bridge, явное восстановление
карантина/UNKNOWN и конечная связка телефон↔VPS остаются незавершёнными.
