# Windows VPS: подготовка проверки связи, НЕ реальная торговля

Эти файлы запускают **существующий упрощённый simulation API** `run_recovery_sim.py`.
Это не MockApplication с поддельным брокером и не реальный MT5-сервис.
Доступны просмотр состояния и тестовая установка/отмена диапазонов. Котировки и
исполнения не поступают, кнопка закрытия позиции возвращает отказ. Не считать
успешное соединение доказательством работы RECOVERY на реальном счёте.

## Что требуется

- Windows VPS, Python 3 (поддерживаемый FastAPI/Pydantic; ориентир 3.11–3.13)
  с `py` launcher. Python и Caddy скачивать только с официальных сайтов.
- Для телефона: Caddy и доменное имя, направленное на VPS; сертификат HTTPS,
  доверенный Android. Домен приведён как вариант установки, не обязательное
  изменение ранее выбранного пользователем адреса. Для HTTPS по IP нужен
  отдельно проверенный доверенный сертификат на IP. Простая подстановка IP в
  Caddyfile не решает это: по умолчанию Caddy может использовать локальный CA,
  которому Android не доверяет. Не отключать проверку TLS в приложении. Самоподписанный сертификат
  с отключением проверки TLS здесь не поддерживается.
- Отдельный случайный ключ минимум 32 ASCII-символа (`A-Z`, `a-z`, `0-9`, `_`, `-`) (одинаковый в приложении и сервисе).
  Не использовать пароль MT5, не вставлять ключ в URL и не отправлять в чат.

## Локальный запуск оператором

Распаковать `server` целиком в постоянный каталог пользователя Windows. Не запускать
из временного ZIP-просмотра. Открыть PowerShell без прав администратора:

```powershell
cd C:\Users\YOUR_USER\MT5-Widget\server\windows
.\Install-Simulation.ps1
.\Start-Simulation.ps1
```

Если локальная политика запрещает PS1, не отключать её автоматически. Следовать
политике администратора; альтернативно вручную создать venv, установить только
`requirements-simulation.txt` и запустить `run_recovery_sim.py` с переменными
`WIDGET_TOKEN` и `RECOVERY_SIM_JOURNAL`. Установщик не меняет ExecutionPolicy.

Launcher отвергает Unicode, пробелы и остальные символы ключа. Ключ вводится скрыто; он доступен дочернему Python-процессу в окружении, а не в
аргументах запуска. Локальный администратор всё равно способен прочитать память.
Состояние находится в `server/simulation-data/recovery-simulation.sqlite3`.
Этот файл не переносить поверх будущей live-БД. Не запускать второй экземпляр
упрощённого simulation API на той же БД: в нём нет process-owner lifecycle
MockApplication. Остановка: Ctrl+C. Закрытие сеанса Windows/перезагрузка может
остановить процесс; автозапуск/служба здесь намеренно не установлены.

## Caddy → loopback

1. Установить Caddy отдельно по официальной инструкции. Копировать
   `Caddyfile.example` в `Caddyfile`, заменить `.invalid` своим именем.
2. Убедиться, что DNS соответствует VPS. Публичный доступ и настройки firewall
   согласуются отдельно; эти скрипты их не меняют.
3. Проверить конфигурацию: `caddy validate --config .\Caddyfile --adapter caddyfile`.
4. Запустить оператором: `caddy run --config .\Caddyfile --adapter caddyfile`.
5. В приложении: адрес `https://имя-сервера` без пути и ключ. Запрос без ключа к
   `/api/recovery/state` должен возвращать 401; с ключом — JSON режима simulation.

Python слушает только `127.0.0.1:8767`. Не открывать 8767 в интернет и не менять
bind на `0.0.0.0`. Caddy завершает TLS и передаёт запрос локально. Не включать
журналирование Authorization/ключа. Убедиться, что порт 8767 занят именно этим
сервисом, а не старой программой. Caddy не гарантирует доступность MT5.

## Что проверено и что нет

Здесь выполнена проверка Python API и тесты проекта в Linux. PowerShell, Caddy,
получение сертификата, Windows firewall, телефон через интернет, перезапуск VPS
и MT5 **не проверялись**. Зависимости ограничены диапазонами, это не воспроизводимый
lockfile: перед поставкой нужен проверенный набор версий для конкретного VPS.
Реальные торговые команды остаются заблокированы. Для готовности live требуются
отдельный native lifecycle/transport, достоверный EA bridge, восстановление
неопределённых исходов и проверка всего пути на Windows. Не подключать эту
инструкцию как автоматическое разрешение реальной торговли.
