# Windows VPS: Python + EA + Caddy, прямой публичный IP

Это пакет подготовки, **не подтверждение готовности к реальной торговле**.
Скрипты ещё не выполнялись на Windows; EA не скомпилирован в MetaEditor,
сертификат не выпущен, соединение с телефоном/брокером не проверено.
Python исполняет стратегию; EA только возвращает историю SL через локальные файлы.
Не запускайте одновременно simulation и native на порту 8767.

## 1. Подготовка без торговли

Установите Windows x64, официальный MT5 своего брокера, совместимый 64-битный Python
с python.org и Caddy из https://caddyserver.com/download. Сохраните версии.
Распакуйте **всю папку server**, не только windows, например в `C:\Recovery\server`.
Не запускайте случайные чужие EA. В скриптах нет скачивания Caddy/MT5, служб,
изменений firewall, ACL, автологина или автостарта торговли.

```powershell
cd C:\Recovery\server\windows
.\Install-Native.ps1 -PythonExe 'C:\Path\To\Python\python.exe'
```

Путь замените фактическим. Установщик создаёт `.venv-native`, ставит зависимости
из requirements.txt, проверяет imports/pip/синтаксис и сохраняет установленный
набор версий в `.venv-native\installed-versions.txt`. Ограничения зависимостей
не являются lock-файлом: повторная установка может выбрать новые версии.
При ошибке совместимости Python/колеса MetaTrader5 остановитесь и исправьте её,
не используйте другой неизвестный пакет. Команда не вызывает MT5.initialize.

Если PowerShell запрещает запуск скрипта, не отключайте политику безопасности:
проверьте происхождение файла и согласуйте способ запуска с администратором VPS.

## 2. MT5 и EA: действия в графическом интерфейсе

1. Откройте нужный `terminal64.exe` под тем же Windows-пользователем, под которым
   будет Python. Войдите самостоятельно в нужный счёт. Сверьте login, точное имя
   торгового сервера и символа с суффиксом. Требуется поддерживаемый hedging-счёт.
2. MT5 → Файл → Открыть каталог данных. Это путь конкретного терминала, не папка
   установки и не Common Files.
3. Скопируйте `server\recovery\mql5\RecoveryEvidenceBridge.mq5` в
   `<каталог данных>\MQL5\Experts\RecoveryEvidenceBridge.mq5`.
   Не перезаписывайте другую версию без сохранения копии.
4. Откройте файл в MetaEditor, F7. Проверьте **0 ошибок** и созданный `.ex5`.
   Наличие исходника само по себе не означает успешной сборки.
5. Добавьте **один** RecoveryEvidenceBridge на график. Укажите ExpectedLogin,
   ExpectedServer, ExpectedSymbol точно как в терминале. Проверьте журнал Experts.
   EA создаёт `<каталог данных>\MQL5\Files\RECOVERY` и работает по таймеру.
   Не используйте диагностический RecoveryDealEvidence вместо этого bridge.
6. Папка RECOVERY должна быть доступна тому же пользователю для чтения/записи;
   посторонние локальные пользователи не должны иметь права записи. Это локальная
   граница доверия, не криптографическая подпись. DLL/WebRequest этому EA не нужны.
7. Проверка реального обмена request/response потребует подходящего исторического
   выхода по SL. Отсутствие ошибок EA ещё не доказывает классификацию полного SL.

Настройки разрешения торговых действий Python в MT5 оператор проверяет отдельно.
Не включайте их для неизвестных программ. Привязка счёта в Python не заменяет
проверку выбранного терминала; Python не переключает счёт автоматически.

## 3. HTTPS по IP

Скопируйте `Caddyfile.native-ip.example` в отдельный `Caddyfile`, замените
`203.0.113.10` своим **статическим публичным IPv4**. Это адрес-пример, он не работает.
Домен не нужен. В файле явно задан Let's Encrypt ACME + `profile shortlived`,
поскольку нельзя рассчитывать на доверие Android к локальному CA Caddy.

```powershell
C:\Path\To\caddy.exe version
C:\Path\To\caddy.exe adapt --config .\Caddyfile --adapter caddyfile --pretty
C:\Path\To\caddy.exe validate --config .\Caddyfile --adapter caddyfile
# Только после проверки IP, прав и доступности портов:
C:\Path\To\caddy.exe run --config .\Caddyfile --adapter caddyfile
```

Запускайте Caddy в отдельном окне PowerShell из `C:\Recovery\server\windows`
и оставьте это окно открытым. Для Python откройте второе окно.

`adapt` должен показать ACME issuer с shortlived, не internal. При неизвестной
директиве profile нужен совместимый официальный Caddy, а не удаление этой настройки.
Успех validate не доказывает выпуск сертификата. `run` связывает публичные порты
и обращается к CA для выдачи сертификата; это отдельный запуск оператором.

Провайдер и Windows должны пропускать входящие 443/TCP и, для HTTP challenge,
80/TCP; не выставляйте 8767 и 2019 наружу. Изменения сетевых правил выполняются
отдельно с разрешением владельца. Caddy работает постоянно, с одним и тем же
пользователем и постоянным хранилищем сертификатов. Не удаляйте его данные.

Проверьте в логах выпуск именно публичного IP-сертификата. С телефона через
мобильную сеть откройте `https://ВАШ_IP`: сертификат без предупреждений, SAN
содержит этот IP, цепочка публично доверенная, срок действителен. Ответ 502 до
запуска Python ожидаем: это проверка TLS, не API. Нельзя использовать HTTP,
`curl -k`, accept-all сертификаты или отключение hostname validation в приложении.
После запуска API проверьте запрос из приложения с ключом и отсутствие доступа
без ключа. Контролируйте продление: один удачный выпуск не доказывает renewal.

Документация: [Caddy TLS issuer/profile](https://caddyserver.com/docs/caddyfile/directives/tls),
[публичные IP и срок 160 часов Let's Encrypt](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability).
Поддержка профиля зависит от установленного Caddy. До проверки выдачи, продления
и доверия Android сетевой этап не считается завершённым.

## 4. Запуск native оператором, не диагностика

Создайте постоянную папку `C:\RecoveryData` с ограниченным доступом для выбранного
Windows-пользователя. Выберите уникальный magic, не используемый другим ботом.
Используйте один случайный ключ минимум 32 ASCII-символа в телефоне и сервере.
Не отправляйте ключ в переписку, не вставляйте его в URL или командную строку.

```powershell
# Второе окно PowerShell, Caddy продолжает работать в первом:
cd C:\Recovery\server\windows
.\Start-Native.ps1 -RunNative -Terminal 'C:\MT5\terminal64.exe' `
  -Account 123456 -BrokerServer 'EXACT-SERVER' -Symbol 'EXACT-SYMBOL' `
  -Magic 123 -Database 'C:\RecoveryData\state.db'
```

Замените все значения. Скрипт запросит ключ скрыто. Он только передаётся дочернему
процессу через окружение, не сохраняется скриптом. Это **native dispatcher**:
сохранённые активные диапазоны могут возобновить брокерские действия сразу.
Поэтому запуск выполняет владелец счёта после проверки состояния и параметров.
Наличие -RunNative не является доказательством безопасности или прибыльности.
Первые соединение/сверка и проверка GUI, частичных исполнений, SL, перезапуска,
потери связи требуют отдельного приёмочного протокола на фактической платформе.

В приложении: `https://ВАШ_IP`, тот же ключ, точные счёт/сервер/символ.
Нельзя использовать устаревший simulation-only APK как доказательство native-связи.
Python слушает только `127.0.0.1:8767`; Caddy передаёт запросы туда.

## 5. Остановка, сбои, резервирование

Ctrl+C останавливает Python, **но не отменяет брокерские ордера и не закрывает
позиции**. SL, уже принятый брокером, остаётся; новые переносы/действия стратегии
при остановленном Python не выполняются. Зависший вызов брокера может задержать
завершение. После принудительного завершения проверьте MT5 перед перезапуском.

Не удаляйте БД, lock или checkpoint ради снятия ошибки. Не повторяйте неизвестный
результат команды новым идентификатором. Сначала сверка журнала/ордеров/сделок,
затем предусмотренная explicit reconcile; порядок описан в документации runtime.
Резервируйте согласованную БД после нормальной остановки, сохраняя связанные
журналы; копирование одного активного SQLite-файла недостаточно.

Для первого этапа процессы foreground. Закрытие окон/выход Windows-пользователя
может прервать работу. Не обещается работа после перезагрузки: Windows service
или Task Scheduler, восстановление MT5 GUI-сессии и секретов требуют отдельной
настройки и теста. Не запускайте MT5 как обычную headless service без проверки
его сессии. Автостарт Python также может возобновить активные диапазоны.

## Что проверено здесь

Статическая проверка файлов и Linux-тесты Python не заменяют Windows PowerShell,
Caddy validation, MetaEditor, брокера или Android. Финальная приёмка должна
фиксировать версии, результаты этих проверок и оставшиеся ограничения.
