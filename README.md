# AI-IMPULS-TRAIDER — стратегия V3.3

Бот девятисценарного hedge-цикла Capital.com для Python/Pydroid 3. Полная спецификация расчётов и
переходов находится в [`docs/SCENARIO_LOGIC_RU.md`](docs/SCENARIO_LOGIC_RU.md).

## Кратко о V3.3

* S1 открывает BUY и SELL с SL и предварительным TP.
* После первого подтверждённого SL Trigger закрытой стороны ставится точно на подтверждённый SL
  оставшейся позиции. Первоначальный entry и дополнительный spread offset не используются.
* Scenario повышается только после подтверждённого actual fill новой позиции.
* Подтверждённый фактический loss `L`, фиксированная денежная цель `T` и ещё не уточнённые expected
  losses сохраняются раздельно. TP равен `(L + unresolved projections + T) / actual size`; SL-
  дистанция к TP не прибавляется и минимальной границей TP не является.
* Expected loss заменяется фактом ровно один раз. Пересчитывается TP открытой позиции и ожидающего
  входа, но не side, Trigger level, SL, size или Scenario.
* Окончательно отклонённый MARKET повторяется для того же одиночного перехода через 60 секунд после
  свежей reconciliation. Неизвестный исход никогда не разрешает дублирующий POST.
* S9 остаётся защищённой до собственного TP либо SL. S10 и принудительного MARKET-close нет.
* Старый `CycleContinuation`, пятиминутная пауза и повторная BUY/SELL-пара удалены.

Фактический P&L считается только по actual entry/close/size: BUY `(close-entry)×size`, SELL
`(entry-close)×size`. Initial spread, SL/Trigger slippage и комиссии отдельно не начисляются.

## Настройки V3.3

Пример содержит:

```json
"SCENARIO_POSITION_SIZES": ["10", "10", "10", "20", "20", "20", "20", "20", "20"],
"SCENARIO_STOP_DISTANCES": ["1", "1", "3", "4", "4", "4", "4", "4", "4"],
"TARGET_PROFIT": "0.3"
```

`TARGET_PROFIT` — пункты прибыли на единицу первоначального объёма; для size 10 значение `0.3`
фиксирует `T=3`. SL-массив остаётся пользовательским. Работающий цикл сохраняет снимки обоих
массивов и не меняется после редактирования config.

Обновление `bot_config.example.json` **не перезаписывает** существующий `bot_config.json`. Если в
пользовательском файле задан `SCENARIO_POSITION_SIZES`, вручную замените четвёртый элемент с `10`
на `20`, чтобы получить согласованный массив V3.3.

## Установка и обновление Pydroid 3

Готовый автоматический загрузчик: [`pydroid_installer.py`](pydroid_installer.py). Он не спрашивает
папку и не использует `input()`/y-n. Для остановленной установки:

1. Убедитесь, что у брокера нет открытых позиций и working orders старой версии.
2. Сохраните `bot_config.json`, SQLite state и сопутствующие WAL/SHM-файлы.
3. Запустите `pydroid_installer.py`; пользовательский config и runtime state сохраняются.
4. Проверьте пользовательский массив объёмов и при необходимости установите
   `[10,10,10,20,20,20,20,20,20]`.
5. Первый новый цикл V3.3 запускайте с S1. Активный цикл прежней стратегии автоматически не
   переносится.

## Запуск и безопасность

```bash
python main.py
```

Сначала используйте `CAPITAL_DEMO=true` и `BOT_DRY_RUN=true`. Перед real-счётом проверьте все
переходы на DEMO минимальным допустимым объёмом. Credentials хранятся только в пользовательском
`bot_config.json`/environment и не должны попадать в Git.

Основной поток применяет broker evidence и сохраняет SQLite; фоновые Telegram/history workers не
изменяют торговое состояние. Durable intents блокируют повторные mutations при неизвестном
HTTP-результате. Пустой `/positions` не очищает неизвестные operations.
