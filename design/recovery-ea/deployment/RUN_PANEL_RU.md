# Локальный запуск чистой панели RECOVERY

Лаунчер в этой ветке только читает конфигурацию и запускает веб-панель.
Он не устанавливает службы, не меняет Caddy/фаервол, не запускает MT5,
не включает торговлю и не отправляет заявки. Работает одним процессом
на `127.0.0.1:8767` (не слушает внешние адреса).

1. Открой в нужном экземпляре MT5 **Файл → Открыть каталог данных**.
   Используй полученный корень, внутри которого находится `MQL5`.
   Лаунчер проверяет только указанный путь:
   `MQL5\Files\RECOVERY_PANEL\sessions`. Он не ищет другой
   терминал и ничего не создаёт, если папок ещё нет.
2. Используй приватный `recovery-profile.json` той же установки
   (`install_id` должен совпадать со `scope_id` EA), либо передай эти
   значения через уже настроенное приватное окружение
   `RECOVERY_SCOPE_ID` и `RECOVERY_PANEL_KEY`. Ключ не передавай
   аргументом PowerShell, в URL или в Caddyfile.
3. Из корня исходников, в среде с FastAPI и Uvicorn, выполни:

```powershell
python design/recovery-ea/deployment/run_panel.py --mt5-data-dir "C:\путь\к\каталогу_данных" --origin "https://vps.example" --profile "C:\приватная_папка\recovery-profile.json" --check
```

`vps.example` и пути здесь примеры. `--check` не открывает порт.
Код 0: профиль читается и обнаружена привязанная запись состояния EA;
3: источник EA недоступен или состояние неизвестно; 2: конфигурация не
прочиталась. Код 0 не подтверждает работающий терминал, поддержку торговых
команд или готовность к реальной торговле. Из-за намеренного отсутствия
проверок по часам файловый статус не считается доказательством живого EA.
Убери `--check` для запуска **лишь панели**; если каталоги есть, а состояние
EA ещё неизвестно, страница видна, но команды ожидания не ставятся в очередь.

### Прокси и локальная проверка

Действующий Caddy на **том же** Windows VPS должен завершать HTTPS и
проксировать `/recovery`, `/recovery/assets/*`,
`/api/recovery/session/*`, `/api/recovery/ea/*` без переписывания пути
на `127.0.0.1:8767`. Нужны исходный публичный Host, доверенный
`X-Forwarded-Proto: https` от loopback-прокси, корректный сертификат и
точное совпадение `--origin` со страницей. Не открывай локальный порт
наружу и не включай журналирование заголовков авторизации. Конфигурацию
прокси этот скрипт не меняет.

Локально GET `http://127.0.0.1:8767/recovery` проверяет только ответ веб-процесса.
Вход и API по прямому HTTP не предназначены для использования; открывай
панель по настроенному HTTPS. Нет публичного health-endpoint,
который раскрывает состояние терминала без сессии.

Авторитет настроек намеренно не назначается: настройка SL на веб-панели
остаётся недоступной, пока настоящий владелец поколения явно не подключён.
Роль советника и брокерские заявки этот лаунчер не проверяет.

Офлайн-тесты: из этого каталога `python -m unittest -v test_run_panel`.
