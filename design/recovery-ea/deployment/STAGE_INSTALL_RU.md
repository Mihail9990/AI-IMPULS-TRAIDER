# Подготовить локальные файлы трёх советников

Это этап проверки и подготовки, **не установщик**. Он принимает исходный
кандидатный ZIP из точного коммита и отдельную папку результатов MetaEditor,
в которой для советника торговли, сверки и цен есть успешно проверенные
логи и EX5. Архив, ожидаемые SHA-256 и происхождение сборки должны браться
из доверенного источника. Самостоятельно вычисленный SHA неизвестного ZIP
не делает его доверенным.

Из корня проверенной копии, где уже есть инструменты сборки:

```powershell
py -3 "design\recovery-ea\deployment\stage_recovery_install.py" --archive $Archive --commit $Commit --archive-sha256 $Pack.zip_sha256 --results $Results
```

Если один из результатов отсутствует, не соответствует роли или не
проходит проверку целостности, скрипт не создаёт папку. При успешном
выполнении он выводит JSON с путём новой временной папки на локальном
диске и SHA-256 её манифеста. Папка каждый раз новая; указать каталог
установки через этот интерфейс нельзя. При ошибке копирования удаляется
только эта попытка подготовки.

В папке ровно `RecoveryTrader.ex5`, `RecoveryVerifier.ex5`,
`RecoveryPriceWatcher.ex5` и `stage-manifest.json`. Манифест связывает
проверенные исходники, хеши исходных логов и скопированных EX5, коммит и
версию компилятора. Сырые машинные логи, ключи, данные счёта и конфигурация
терминала не копируются. Проверка сопоставляет результаты; она не
подтверждает подпись издателя и не проверяет работу у брокера.

Скрипт не ищет установленный каталог MT5, не копирует в него, не запускает
терминал или советников, не меняет Caddy и брандмауэр. Установка и запуск
этим шагом не выполняются. Проверка `python -m unittest -v
test_stage_recovery_install.py` использует временную папку и поддельный
компилятор. Нативная сборка Windows и проверка установщика на чистой VPS
остаются отдельными шагами.
