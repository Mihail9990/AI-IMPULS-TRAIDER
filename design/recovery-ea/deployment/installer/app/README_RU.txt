RECOVERY для MetaTrader 5 — подготовка нового компьютера

Запускайте RECOVERY.cmd из установленного приложения под той же учётной записью Windows, что и выбранный терминал. Мастер использует поставляемый Python 3.13 x64 и библиотеки панели. Подготовка выполняется офлайн. Для работы наблюдателей нужен установленный официальный MetaTrader 5 с подключением к выбранному брокерскому счёту. Для работы RecoveryTrader требуется хеджинговый счёт.

Новый профиль и первый сеанс

1. В нужном MT5 откройте «Файл → Открыть каталог данных». Проверьте, что в MQL5\Experts\RECOVERY находятся RecoveryVerifier.ex5, RecoveryPriceWatcher.ex5 и RecoveryTrader.ex5. При необходимости обновите список советников в «Навигаторе». Оставьте Algo Trading выключенным во время подготовки.

2. Откройте RECOVERY.cmd и выберите 1. Придумайте имя профиля для этой установки и счёта. Введите каталог данных, точные номер счёта, сервер и символ из MT5, а также свой положительный Magic для этой стратегии. Публичный origin — точный HTTPS-адрес вашего существующего прокси, например https://trade.example.com, без пути и завершающей косой черты. Для диагностики на компьютере можно ввести https://localhost.

3. Задайте имя сеанса и откройте выведенную мастером папку. Профиль и ключ панели лежат в %LOCALAPPDATA%\AI-IMPULS-RECOVERY\profiles\<имя>\recovery-profile.json. Права каталога на NTFS получают текущий пользователь Windows, SYSTEM и локальные администраторы. Два файла .set лежат в подпапке sessions\<сеанс>. В повторной подготовке с тем же именем сохраняются этот ключ, привязка счёта и идентификаторы незавершённого сеанса.

4. Откройте три отдельных графика одного указанного символа. Третий график для RecoveryTrader должен быть M1. На первый график вручную подключите RecoveryVerifier и в параметрах загрузите RecoveryVerifier.set. На второй таким же образом подключите RecoveryPriceWatcher с RecoveryPriceWatcher.set. Обе роли только наблюдают и могут инициализироваться с выключенным Algo Trading.

5. На вкладке «Эксперты» найдите появившиеся у этих двух ролей строки «RECOVERY verifier ready to observe; chart ID …» и «RECOVERY price watcher ready to observe; chart ID …». Выберите в RECOVERY.cmd действие 2, тот же профиль и сеанс. Вставьте обе строки целиком или введите их номера. При вводе одного номера мастер сверит его со строкой соответствующей роли в MQL5\Logs выбранного терминала. Если файл журнала ещё не обновился, скопируйте строки с вкладки «Эксперты». Убедитесь, что обе строки относятся к текущим графикам, символу и загруженным .set. Полученный RecoveryTrader.set предназначен для третьего графика. Сам советник сверяет ChartID при подключении. Период M1, начальная дистанция 0.80, порог поддержки 0.40 и 24 размера лота записаны в пресет.

6. После проверки параметров решение о подключении RecoveryTrader и разрешениях алгоритмической торговли принимает владелец. При выключенных разрешениях этот советник не инициализируется. Мастер не подключает советников, не переключает счёт или Algo Trading и не нажимает кнопки ожидания. После осознанного подключения основной советник создаёт рабочую папку и публикует состояние нового сеанса.

При новом запуске всех трёх ролей используйте действие 1, прежний профиль и НОВОЕ имя сеанса. Затем снова загрузите два новых .set, возьмите актуальные ID и выполните действие 2. Это даёт новый случайный идентификатор запуска. Старый каталог можно оставить для справки. Дубликат запуска с уже использованным сеансом основной советник отвергает.

Проверка и запуск панели

Действие 3 выполняет штатную предварительную проверку без открытия порта. Код 0 означает, что читаются конфигурация и привязанная запись состояния. Код 2 означает, что конфигурация или каталог данных ещё недоступны. Код 3 означает, что состояние EA ещё неизвестно. При отсутствии MQL5\Files\RECOVERY_PANEL\sessions ожидайте штатного ручного запуска владельцем. Запись состояния подтверждает чтение файла. Живой обмен ролей нужно проверять отдельно.

Действие 4 сначала проводит ту же проверку. При успехе оставьте это окно открытым. Локальная страница доступна по http://127.0.0.1:8767/recovery. Остановить веб-процесс можно Ctrl+C. Панель слушает только 127.0.0.1. Прямой HTTP подходит для проверки загрузки страницы. Для входа и команд используйте доверенный HTTPS-прокси с тем же origin, который передан панели.

Если Caddy уже обслуживает ваш домен на этом компьютере, владелец прокси может добавить следующие строки внутрь действующего блока сайта, сохранив обработчики остальных путей:

    @recovery path /recovery /recovery/assets/* /api/recovery/session/* /api/recovery/ea/*
    handle @recovery {
        reverse_proxy 127.0.0.1:8767
    }

Путь запроса должен оставаться исходным. Нужны публичный Host, корректный X-Forwarded-Proto: https и действительный доверенный сертификат. Открывайте https://<ваш-домен>/recovery. Мастер не изменяет Caddy, DNS, брандмауэр и службы Windows. Владелец может локально прочесть panel_key в своём приватном JSON и ввести его в форме входа по HTTPS. Держите ключ отдельно от адресной строки, переписки и журналов.

Уже есть приватный профиль и пресеты

Сохраните прежнюю конфигурацию. Выберите действие 5 (проверка) или 6 (запуск). Укажите абсолютный путь к существующему recovery-profile.json, каталог данных его MT5 и фактический HTTPS origin. Эти действия читают указанный JSON и не требуют повторной подготовки наблюдателей. Имеющиеся role-session.json, файлы .set и настройки счёта сохраняются. Этот путь также позволяет задать действующий HTTPS origin после локальной диагностики. Для нового независимого счёта используйте действие 1 с отдельным именем профиля.

Для запуска непосредственно нужного действия используйте RECOVERY.cmd prepare, bind, check, start, existing-check или existing-start. Аргументы выбирают только действие. Параметры вводятся в окне мастера.
