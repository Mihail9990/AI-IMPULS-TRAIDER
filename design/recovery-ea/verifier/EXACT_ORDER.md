# Точная сверка ордера по известному тикету

Дополнение к инвентаризации и истории позиции для случая, когда тикет ордера
известен, а идентификатор позиции ещё не возник. Например, неисполненный или
отменённый ордер может иметь `position_identifier=0`. Не искать «похожий» ордер
по цене, времени или объёму и не делать вывод об отсутствии отправки.

Торговый EA запрашивает точный тикет через `RecoveryExactReportRequest` и читает
ответ сверки напрямую через `RecoveryExactReportRead`. Обе операции работают с
локальной файловой песочницей MT5, Python не нужен для передачи. Компонент
ничего не отправляет брокеру. Универсальный торговый цикл и маршрутизация
незавершённых команд в этот запрос остаются отдельной работой.

В том же каталоге `RECOVERY_VERIFY`, что у инвентаризации и истории,
однострочный create-only запрос `<nonce>.ord` (табуляция, UTF-8, LF либо CRLF):

```text
RECOVERY_EXACT_ORDER_REQUEST_V1 nonce executor_epoch verifier_epoch generation login server symbol magic order_ticket END
```

Создавать новый nonce для каждого наблюдения и уникальный временный тег для
публикации. Перед ответом советник сверки проверяет текущий счёт, сервер, символ
и magic, выбирает точный текущий ордер или, при отсутствии, точный ордер из
истории. Успешное наблюдение повторяется и должно совпасть. Это не замена
проверке итогового эффекта сделки. Внутренний список исторических ордеров
меняется вызовом [HistoryOrderSelect](https://www.mql5.com/en/docs/trading/historyorderselect);
отдельная итерация по истории позиции заново выбирает свои данные.

Файл `<nonce>.order` публикуется без замены; чтение требует полного совпадения
запроса, включая ожидаемый график советника сверки:

```text
RECOVERY_EXACT_ORDER_V1 nonce executor_epoch verifier_epoch generation login server symbol magic verifier_chart sequence order_ticket coverage reason
E current_or_history position_identifier magic order_type order_state initial_volume remaining_volume order_price SL TP stop_limit
END
```

Ровно одна запись E при `observed/ok`, ни одной при
`unavailable/{unknown,mismatch,read,changed,session}`. Если связанный счёт
недоступен, ответ может не появиться. Любой неуспех оставляет исход команды
неподтверждённым и не разрешает повтор. MT5-тип и состояние передаются как есть:
исторический источник сам по себе не означает ни отмену, ни полное исполнение.
Денежные и ценовые поля не нормализуются; их сравнивает вызывающий компонент.
Нет контроля по часам, возрасту котировки или телефону.

`python -m unittest discover -v` из `verifier/` проверяет канонический протокол,
создание без перезаписи и обмен действительных/невалидных записей через C++
shim. Это не компиляция MetaEditor, не проверка файлового обмена в MT5 и не
прогон на брокерском счёте.
