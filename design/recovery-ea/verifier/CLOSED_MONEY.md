# Отдельный учёт результата закрытия

`RecoveryClosedMoney.mqh` принимает ранее подтверждённый полный набор выходов
одной позиции. У каждого выхода связываются тикет сделки, постоянный ID
позиции, тикет закрывающего ордера, направление и точный объём. У неполного
набора, дубликатов, несовпадений, недоступной истории и изменений между
двумя чтениями нет положительного результата.

Чтение использует фактические signed
[DEAL_PROFIT, DEAL_COMMISSION, DEAL_SWAP и DEAL_FEE](https://www.mql5.com/en/docs/constants/tradingconstants/dealproperties)
в валюте выбранного счёта. Убыток для записи — `max(0,-net)`, где
`net = profit + commission + swap + fee`. Проскальзывание не пересчитывается
по цене SL: фактическая цена уже учтена брокером в прибыли сделки. Сумма
включает только перечисленные выходные сделки (`DEAL_ENTRY_OUT`), не
отдельные начисления и не комиссии входных сделок. Закрытия через close-by и
другие формы отражения требуют отдельной сверки.

Эта сверка не меняет SL, цену входа, направление, счётчики/шаг стратегии и
не блокирует сопровождение нового входа. При нехватке фактов учёт остаётся
неразрешённым, не превращается в нулевой результат. Формат существующей
истории V1 не меняется. Остаётся связать с отдельной задачей сверки и
долговременным журналом (идемпотентность между попытками) по счёту и точным
тикетам, не вызывая чтение посреди перебора другого списка истории.

`python -m unittest -v test_closed_money_compat.py`: тесты с подставными
ответами MT5 и проверкой целостности; не компиляция MetaEditor и не прогон на
брокерском счёте.
