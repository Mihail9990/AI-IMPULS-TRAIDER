# Отдельный учёт результата закрытия

`RecoveryClosedMoney.mqh` принимает ранее подтверждённый полный набор выходов
одной позиции. У каждого выхода связываются тикет сделки, постоянный ID
позиции, тикет закрывающего ордера, направление и точный объём. У неполного
набора, дубликатов, несовпадений, недоступной истории и изменений между
двумя чтениями нет положительного результата.

Чтение использует фактические signed
[DEAL_PROFIT, DEAL_COMMISSION, DEAL_SWAP и DEAL_FEE](https://www.mql5.com/en/docs/constants/tradingconstants/dealproperties)
в валюте выбранного счёта. Убыток для записи — `max(0,-net)`, где
`net = profit + commission + swap + fee`. Проскальзывание не пересчитывается
по цене SL: фактическая цена уже учтена брокером в прибыли сделки. Сумма
включает только перечисленные выходные сделки (`DEAL_ENTRY_OUT`), не
отдельные начисления и не комиссии входных сделок. Закрытия через close-by и
другие формы отражения требуют отдельной сверки.

Эта сверка не меняет SL, цену входа, направление, счётчики/шаг стратегии и
не блокирует сопровождение нового входа. При нехватке фактов учёт остаётся
неразрешённым, не превращается в нулевой результат. Формат существующей
истории V1 сохраняется.

После подтверждения полного закрытия основной советник берёт список выходных сделок
из той же независимой истории. После торгового шага таймера он сверяет денежные
свойства одной позиции за проход. В каталоге данных терминала открой
`MQL5\Files\RECOVERY_PANEL\closed-money`. Каждая позиция имеет один итоговый
`<хеш сервера и счёта>-<ID позиции>.tsv`. В нём указаны цены фактического
исполнения, уровни SL, тикеты и суммы в валюте счёта. Для суммарного результата
по счёту складывай столбец `net` из итоговых файлов одной валюты.
Полный выход по ранее установленному TP и несколько выходов с разными
причинами также дают денежный результат, если суммарный объём и отсутствие
остатка подтверждены. Торговый переход по ним по-прежнему требует отдельного
правила стратегии.

Суффикс `.pending.tsv` означает, что список выходов подтверждён, а денежный
результат ожидает сверки. На каждом таймере советник по очереди возвращается
к таким позициям, в том числе после возврата к ручному ожиданию. При снятии
советника с графика незавершённая запись остаётся на диске для сверки владельцем.
Если оба файла сохранились после прерванной очистки, учитывай только итоговый
файл со строкой `observed`. Повторная доставка доказательства сохраняет тот
же файл. Несовпадающую версию уже опубликованного результата советник сохраняет
для разбора в статусе ожидания.

`python -m unittest -v test_closed_money_compat.py`: тесты с подставными
ответами MT5 и проверкой целостности; не компиляция MetaEditor и не прогон на
брокерском счёте.
