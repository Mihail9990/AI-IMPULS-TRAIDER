# Передача команды из веб-панели торговому EA (V1)

`web_handoff.py` подключается к существующему `Channel`. Он публикует
только канонический JSON по уже опубликованному протоколу. Не импортирует MT5,
не запускает Python-исполнитель и не вызывает торговые функции.

Локальный веб-процесс передаёт секрет bearer-аутентификации через серверную
конфигурацию. Не встраивать его в публичный JS, URL или логи; внешний браузер
должен использовать существующий защищённый веб-вход. Не открывать этот
внутренний HTTP-адаптер наружу. Рабочая папка должна быть приватной, на
локальном NTFS с поддержкой hard link, иначе публикация не подтверждается.
Команды и квитанции действуют только в текущем сеансе EA. Перед публикацией
`state.json` владелец нового сеанса создаёт новый, никогда ранее не
использованный `boot_id` и пустые каталоги
`sessions/<boot_id>/commands` и `sessions/<boot_id>/receipts` в общем
приватном корне. Текущий EA читает только свою папку и сверяет
`boot_id/context_id/generation_id` записи. Папки прошлых сеансов и старые
плоские `commands` / `receipts` не читаются и не импортируются; их
наличие не мешает новому сеансу. Из старого состояния цикл не восстанавливается,
отдельного режима блокировки на перезапуск нет. Настройки и обычная
история сделок от командной очереди не зависят.

- `GET /api/recovery/ea/state` возвращает контекст и режим без служебных полей.
- `POST /api/recovery/ea/manual_wait` и `.../manual_cancel` принимают
  ровно `request_id`, `expected_boot`, `expected_context`,
  `expected_generation` как канонические UUID и `confirmed: true`.
  Отдельных часов, токенов годности по времени или новых галочек нет.
- `GET /api/recovery/ea/commands/{request_id}` возвращает статус по сохранённой
  записи с обязательным параметром `?expected_boot=<boot_id>` и проверяет
  привязку квитанции. Перезапуск HTTP-процесса без смены сеанса EA не
  меняет статус; после смены сеанса старые команды не читаются.
  Публикация команды не означает принятие; принятие не означает исполнение.
  Неизвестный результат не разрешает повторную отправку. Совпадающий
  сохранённый ID только читает статус; чужая команда с тем же ID отклоняется.
- `POST /api/recovery/ea/configure_ranges` принимает те же поля подтверждения
  и дополнительно ровно один объект `payload`:

  ```json
  {"ranges":[{"range_id":1,"side":"BUY","price":"4000.00"},{"range_id":2,"side":"SELL","price":"3999.850"}]}
  ```

  В списке один или два элемента с уникальными целочисленными номерами
  `1`/`2`. Допустимые стороны `BUY` и `SELL` передаются как выбраны.
  Цена строго положительная десятичная строка: целая часть с 1–15
  цифрами без ведущих нулей (кроме `0`), дробная часть при наличии
  с 1–16 цифрами после точки. Строка и порядок элементов сохраняются
  без округления. Линии графика и рыночные команды не входят в этот формат.
  Проверка допустимого шага цены и выполнение остаются за EA. Та же пара
  ID + сеанс с изменённой стороной, ценой или содержимым списка означает
  конфликт запроса, а не повторную отправку.

Офлайн-тест: из этого каталога `python -m unittest -v test_channel test_web_handoff`.
Используется FastAPI и его тестовый HTTP-клиент. Это отдельно проверенный
адаптер, а не готовый веб-релиз: маршруты ещё нужно подключить к существующей
панели, а торговый EA должен создать и использовать свою папку сеанса.
Проверки адаптера не запускают MT5 и не отправляют заявки.
