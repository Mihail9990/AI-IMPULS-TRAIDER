# Передача команды из веб-панели торговому EA (V1)

`web_handoff.py` подключается к существующему `Channel`. Он публикует
только канонический JSON по уже опубликованному протоколу. Не импортирует MT5,
не запускает Python-исполнитель и не вызывает торговые функции.

Локальный веб-процесс передаёт секрет bearer-аутентификации через серверную
конфигурацию. Не встраивать его в публичный JS, URL или логи; внешний браузер
должен использовать существующий защищённый веб-вход. Не открывать этот
внутренний HTTP-адаптер наружу. Рабочая папка должна быть приватной, на
локальном NTFS с поддержкой hard link, иначе публикация не подтверждается.
Команды и квитанции действуют только в текущем сеансе EA. Перед публикацией
`state.json` владелец нового сеанса создаёт новый, никогда ранее не
использованный `boot_id` и пустые каталоги
`sessions/<boot_id>/commands` и `sessions/<boot_id>/receipts` в общем
приватном корне. Текущий EA читает только свою папку и сверяет
`boot_id/context_id/generation_id` записи. Папки прошлых сеансов и старые
плоские `commands` / `receipts` не читаются и не импортируются; их
наличие не мешает новому сеансу. Из старого состояния цикл не восстанавливается,
отдельного режима блокировки на перезапуск нет. Настройки и обычная
история сделок от командной очереди не зависят.

- `GET /api/recovery/ea/state` сообщает точный контекст и режим:
  `ready`, `manual_wait`, `pending_wait`, `active` или `unknown`.
- `POST /api/recovery/ea/manual_wait`: ждать ручную позицию.
- `POST /api/recovery/ea/manual_pending_wait`: ждать ручной триггер-ордер.
  Ордер выставляет пользователь в MT5; при нескольких подходящих
  ордерах EA не выбирает наугад. Панель не передаёт тикет, цену, тип,
  диапазон или произвольные инструкции.
- `POST /api/recovery/ea/manual_cancel`: выключить ожидание в любом из
  двух режимов. Ордер, позицию и SL команда в MT5 не удаляет и не меняет.
- Каждый POST принимает ровно `request_id`, `expected_boot`,
  `expected_context`, `expected_generation` как канонические UUID и
  `confirmed: true`. В канонической записи очереди `payload={}`.
  Кнопок и API для настройки диапазонов нет. Часы не сверяются.
- `GET /api/recovery/ea/commands/{request_id}?expected_boot=<boot_id>`
  читает только статус запроса этой сессии. Запись команды в очередь
  не означает принятие, принятие не означает смену режима, а подтверждение
  смены режима не означает, что SL уже выставлен. Не повторять POST при
  неоднозначном результате.

Офлайн-тест: из этого каталога `python -m unittest -v test_channel test_web_handoff`.
Используется FastAPI и его тестовый HTTP-клиент. Это отдельно проверенный
адаптер, а не готовый VPS-релиз. Маршруты подключены к исходнику панели;
торговому EA нужно создать и проверить реальную папку сеанса.
Проверки адаптера не запускают MT5 и не отправляют заявки.
