# Офлайн-ядро переходов RECOVERY

`RecoveryCycle.mqh` не читает терминал и не отправляет ордера. Сверено с
`runtime/server/recovery/{engine,native_initial_reverse,native_support_reentry,native_close_ledger,volume_schedule}.py`
из RECOVERY WEB 0.1.7. При расхождении симулятора с нативным модулем
размер уже выставленного встречного ордера не меняется.

- У каждого диапазона свой счётчик. Подтверждённое полное закрытие по
  начальному SL продвигает шкалу; ручное закрытие и SL поддержки не продвигают.
- Для следующего встречного ордера резервируется следующий слот. На позиции
  № 24 новый встречный ордер не планируется. После 24 полного SL требуется
  отменить оставшиеся ордера этого диапазона; это намерение, не отчёт об отмене.
- BUY использует BID, SELL использует ASK. Движение по настраиваемым порогам (по умолчанию 0,25 и 0,40) даёт только
  предложение переноса; предложение не меняет подтверждённый тип SL.
- После подтверждённого SL поддержки цена переоткрытия считается от
  подтверждённого уровня стопа, а не цены закрытия. Существующий встречный
  ордер до этого перехода не меняется и не отменяется этим ядром.
- Переданное доказательство закрытия означает полную историю всех выходов по
  конкретной позиции, с однородным типом и уровнем. Для SL принимается только
  точное сопоставление уровня из `DEAL_SL` с подтверждённым журналом защиты.
  При смешанном, неизвестном или двусмысленном уровне переход не выполняется.

Нужны внешний исполнитель и журнал: проверка терминала, учётной записи и
символа, подтверждённые сделки, ожидаемый тикет из сохранённого намерения,
защита от повторов по **всей** цепочке, атомарная фиксация перехода и его
намерения. Сохранённые последние тикеты защищают только от немедленного
повтора. Они не заменяют журнал. Пока запись о закрытии не разрешена, не
создавать новые ордера, даже при наличии вероятной причины закрытия.
Переоткрытие и встречный ордер требуют проверок фактической защиты,
дистанции и существующих заявок; этот модуль не разрешает их отправку.

Это не полный перенос. В частности, отдельно нужны обработка немедленного
закрытия до штатного учёта входа, привязка ручного подхвата к циклу, переход
после TP, замена встречного ордера, хранение P/L и тесты MT5. При дробном
относительно тика среднем входе внешний слой должен согласовать способ
представления; это ядро принимает только точные целые единицы и не округляет.

```sh
g++ -std=c++17 -Wall -Wextra -Werror -pedantic -fsanitize=undefined \
  -o /tmp/recovery-cycle-test test_recovery_cycle.cpp
/tmp/recovery-cycle-test
```
