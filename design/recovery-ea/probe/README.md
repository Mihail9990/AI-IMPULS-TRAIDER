# Проверка прямого обмена двух EA

`RecoveryPairProbe.mq5` — диагностический EA, не торговый советник.
Он использует тот же отправитель запроса и тот же читатель ответа, что
предназначены для торгового EA. Здесь нет Python, отправки или изменения
ордеров. Ограничение демо относится **только к диагностическому EA**.
Эти параметры не будут дополнительными настройками пользователя в панели.

Для проверки после компиляции в MetaEditor:

1. Сохранить структуру каталогов `probe/`, `execution/`, `verifier/` под
   `MQL5/Experts`. Открыть два графика одного символа в одном демо-терминале.
2. На первом запустить `RecoveryVerifier` с параметрами демо-счёта и двумя
   разными 32-значными шестнадцатеричными токенами текущего запуска.
3. На втором запустить `RecoveryPairProbe` с теми же параметрами, ID
   первого графика и новым независимым 32-значным nonce. Идентификатор
   графика получается через [ChartID](https://www.mql5.com/en/docs/chart_operations/chartid).
4. В журнале второго EA ожидается `direct response confirmed`; даже пустой
   снимок допустим, если ответ прочитан и подтверждён. При некорректном ID
   графика, подменённом ответе или остановленном первом EA подтверждения
   быть не должно. Времени действия торговой заявки здесь нет.
5. Повторить после остановки и перезапуска с новыми токенами. Не использовать
   старые файлы для подтверждения новой попытки.

Чтение и отправка работают по [таймеру EA](https://www.mql5.com/en/docs/eventfunctions/eventsettimer)
без ожидания тика; после публикации запрос не повторяется. Это только проверка
обмена, не проверка торгового цикла, исполнения или готовности в реальном времени.

Офлайн: `python -m unittest -v test_pair_probe_compat.py` проверяет
последовательность отправки и приёма на C++-имитации терминала. Тест не
запускает MT5 и не проверяет компиляцию в MetaEditor.
