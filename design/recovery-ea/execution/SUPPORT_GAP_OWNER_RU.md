# Встречный STOP исполнился между выходом и повторным входом

Этот путь применим только после независимо подтверждённого выхода по
SL поддержки на фактическом входе. Из таймера сначала проверить
`RecoveryBeginSupportGapOwner` для текущей задачи закрытия, до обычного
перехода или отправки повтора. Она открывает независимый точный опрос
только если локальный запрос **известного** старого встречного тикета
видит исторический FILLED. Локальная подсказка не является доказательством
и не заменяет старый подтверждённый выход. Нет поиска по цене или
вывода из отсутствия ордера. При активном опросе не запускать одновременно
старый путь повторного входа по той же позиции.

Допустимы три случая: повтор ещё не подготовлен; повтор подготовлен,
но не зарезервирован/не отправлялся; точный повтор окончательно остановлен
до вызова OrderSend. Пустой тикет сам по себе ничего не доказывает.
Для последнего случая принимаются только RD_NOT_SENT и отсутствие записи
или RD_RESERVED_NOT_SENT и точная запись о резервировании без тикета
(не запрос с неизвестным эффектом). Эта проверка действует на конкретный
синхронный RR_REENTRY, не на асинхронные операции.

`RecoveryStepSupportGapOwner` соединяет полный факт выхода с отдельными
точными отчётами об исполнении старого встречного STOP и его новой
позиции. Новый снимок также не должен показывать закрытого предшественника.
Результат RSG_READY подготавливает следующий встречный по фактической
цене входа; размер текущей ступени и счётчик полных стопов не меняются.
Вызвать `RecoveryDispatchSupportGapOwner` один раз после RSG_READY;
на RSG_FINAL никаких следующих заявок не готовится. Неясный результат
не разрешает возобновить ни этот опрос, ни повтор старой стороны.
Никаких часов, восстановления прежнего сеанса или отмены позиции.

Сверка и отправка не атомарны у брокера. Если повтор уже ушёл с неясным
эффектом, этот узкий путь не выбирает сторону и не выдумывает отсутствие
ещё одного ордера. Для известного тикета повтора есть отдельная сверка
пары. Если новая позиция уже отличается от прикреплённого брокером SL,
действующий чистый редьюсер гэпа оставляет результат неясным.

`python execution/test_support_gap_owner_compat.py -v` использует
C++/UBSan и подменённый шлюз; отдельно работают хост-тесты чистого
перехода и точного разбора отчётов. MT5 и MetaEditor не запускались.
