# Сборка типовых запросов торгового EA

`RecoveryOrderRequest.mqh` преобразует рассчитанное намерение в
[MqlTradeRequest](https://www.mql5.com/en/docs/constants/structures/mqltraderequest).
Вызовов отправки и проверок времени нет. Тестируется офлайн постановка
BUY STOP/SELL STOP, перенос своего триггера без запроса изменения объёма,
изменение SL позиции с сохранением проверенного TP и отмена точного тикета.

Цены в намерении заданы в целых тиках инструмента, объём в целых шагах.
Модуль не меняет уровни для обхода брокерских ограничений, не создаёт рыночный
ордер взамен стоп-ордера и не выводит исполнение из сформированного запроса.
Обычные стоп-ордера этой стратегии бессрочные (GTC); изменение чужих приказов,
заявок с иным сроком действия, stop-limit и рыночное закрытие сюда не входят.

Торговый EA должен заново сверить счёт, символ, идентификаторы и параметры
перед выполнением конкретного запроса. Нужны проверки доступности типа заявки
и объёма у брокера, сохранённое намерение, подтверждение результата и обработка
отказа. Этот модуль не является готовым торговым советником.

Офлайн: `python -m unittest -v test_order_request_compat.py`.

`RecoveryActionRequest.mqh` связывает сборщик с зарезервированным действием
диапазона: исключает чужой диапазон и идентификатор операции, передаёт точный
тикет позиции для SL и не обнуляет подтверждённый TP. Для отмены требуется
совпадение тикета и параметров известного ордера. Это локальная проверка
намерения, не наблюдение исполнения у брокера.

Для нативной проверки совместимости этих заголовков предназначен
`probe/RecoveryCompileProbe.mq5`. Его можно компилировать отдельно, не
запуская MT5. Это не торговый советник и не проверка полного цикла.
