# Опрос доказательства встречного исполнения

`RecoveryAlternatingPump` — один конечный автомат в памяти основного
советника на один точный тикет и один кандидат исполнения. Он вызывает
штатные локальные файловые транспорты сверщика; торговые API не вызывает.

1. Владелец знает точный тикет из текущей пары или уже наблюдаемого
   встречного ордера. Он создаёт три никогда не использованных nonce и тег
   публикации. В `RecoveryAlternatingEvidenceBinding` задаёт настоящий
   диапазон, полномочия сверщика, тик цены, шаг объёма, нижнюю границу
   номера отчёта в той же эпохе, и оставляет `history.position_identifier=0`.
   Для ожидающей пары передаёт её исходный точный RRAction; для уже
   подтверждённой — RR_NONE. Не запускать от отсутствия ордера.
2. Владелец вызывает `RecoveryAlternatingPumpBegin()` на новом объекте
   в состоянии RAP_UNUSED. Он выделяет один автомат на рассматриваемое
   исполнение, а не по одному на каждое уведомление MT5. В текущем моменте
   советник-сверщик уже запускается на своём графике и владеет папкой
   `RECOVERY_VERIFY`. Проверка актуальности boot и авторитетного поколения
   остаётся у владельца.
3. Владелец вызывает `RecoveryAlternatingPumpStep()` из своего
   `OnTimer`/планировщика. Один шаг либо публикует один probe, либо читает
   ответ одной стадии. Идентификатор позиции берётся только из точного
   FILLED исторического ответа; затем запрашиваются история и снимок в этом
   порядке. При `RAP_PROOF` выход содержит подтверждённое наблюдение,
   которое в этом же вызове передаётся соответствующему переходу стратегии
   ровно один раз; программа не сбрасывает автомат, чтобы повторить результат.
4. `RAP_WAIT` означает, что штатный парсер ещё не вернул читаемый ответ.
   Он не отличает отсутствующий ответ от повреждённого; повторять можно
   чтение, но не публикацию. `RAP_STOPPED` означает конечное состояние,
   неизвестный эффект публикации, несогласованное доказательство или
   изменение области. Ни один исход не разрешает повторять торговую заявку.
   Новый read-only probe допустим по новому точному событию и с новыми nonce,
   не по таймеру свежести и не для слепого повторения.

Ограничение: автомат покрывает обычный встречный переход. Он не соединён с
рабочим торговым EA, не восстанавливает историю сеанса после запуска и не
заменяет отдельные сценарии поддержки, частичного закрытия и гэпа. Остались
распределитель nonce, владелец текущего контекста, приём исходного события,
привязка `OnTimer` и передача доказательства в состояние советника.
Компиляция MetaEditor не выполнена.
