# Сохранение идентификатора заявки до отправки

`RecoveryIntentJournal.mqh` хранит неизменяемую резервацию идентификатора и,
когда он точно известен, тикет брокерского ордера. Он не вызывает торговые
функции и пока не подключён к торговому EA.

- До потенциальной отправки исполнитель сохраняет полное намерение и его
  канонический хеш. В журнал передаёт тот же постоянный ID, счёт, сервер,
  символ, magic и поколение; ID нельзя генерировать заново после сбоя для
  той же попытки. Журнал не заменяет сохранение параметров и цикла.
- После перезапуска запись «зарезервировано» без тикета означает только
  неизвестный исход. Наличие тикета означает возможность сверить именно этот
  ордер, а не успех операции. Отсутствие файла само по себе не разрешает
  повторную отправку. Неоднозначные файлы не перезаписываются.
- Нет часов, тайм-аута заявки, нового пользовательского подтверждения или
  настройки. Сохранение относится к конкретному намерению, не ко всей торговле.

Файлы находятся в локальном каталоге MT5, не FILE_COMMON. После проверки
длины и записи временного файла используется [FileFlush](https://www.mql5.com/en/docs/files/fileflush),
затем [FileMove](https://www.mql5.com/en/docs/files/filemove) без перезаписи и
чтение результата обратно. Это не доказательство атомарности с операцией у
брокера или переживания сбоя питания. Защищённый каталог, один владелец
торговых действий и тестирование с перезапуском MT5 всё ещё необходимы.

Офлайн-проверка: `python -m unittest -v test_intent_journal_compat.py`.
C++-имитация файловой системы проверяет повторную резервацию, чтение после
перезапуска, неподходящий контекст, обрыв записи и точный 64-битный тикет.
Это не тест Windows или MetaEditor.

## Перезапуск между приёмом заявки и сохранением тикета

`RecoveryIntentRestart.mqh` читает журнал для одного намерения и выбирает только
наблюдение. После сбоя до записи тикета причина `broker_ticket_unknown`.
Даже если в списке есть похожий ордер, этот результат не меняется. Повтор той же
резервации отвергается. С известным тикетом выбирается сверка конкретного
ордера; путь к истории позиции выбирается только при отдельно сохранённой
доказанной связи этого ордера с ID позиции. Ни один результат не означает успех
торговой команды или разрешение отправить её заново. Для уже отменённого
неисполненного ордера без позиции отдельное точное чтение ещё нужно подключить.

[MetaQuotes](https://www.mql5.com/en/docs/constants/structures/mqltraderesult)
различает `request_id` терминала и `order` брокера. Первый не подставляется
вместо брокерского тикета после перезапуска. Причины предназначены для
существующего журнала, а не новых кнопок; подключение к журналу ещё предстоит.

`python -m unittest -v test_intent_restart_compat.py` моделирует сбой сразу после
приёма заявки, до записи тикета, и случай после успешной записи. На демо ещё нужно
проверить реальное повторное чтение известного тикета, отсутствие дубля, видимость
существующей защиты и сохранность другого диапазона.
