# Владелец перехода после закрытия по безубытку

Этот слой не отправляет торговых заявок и не сохраняет состояние для
перезапуска. Он связывает уже независимо подтверждённый выход с новым
чтением прежнего встречного ордера и резервирует ровно один прежней стороны.

1. Из истории и полного снимка позиций построить `RCCloseCheckpoint`
   через `RCCPStageFromWire`. Передать в него ту же настроенную дистанцию,
   что используется для обычного встречного триггера. Для этого перехода
   наблюдаемый уровень SL равен фактической цене открытия, позиция закрыта
   полностью и действие переноса ранее подтверждено независимой сверкой.
2. `RecoveryBeginSupportCloseOwner` принимает этот чекпоинт и максимальный
   порядковый номер двух использованных ответов. Изменение стадии зависит
   от порядка чтения, не от часов. Запрос привязан к текущему сеансу,
   поколению, ревизии, позиции и точному известному встречному тикету.
3. Первый `RecoveryStepSupportCloseOwner` публикует запрос проверки. Пока
   ответ не доступен, состояние диапазона не меняется. Только наблюдение
   более поздней последовательности, с исходным рабочим STOP, его
   направлением, ценой, SL и неизменным объёмом разрешает резервирование.
   Исторический уже исполненный тикет, пропавшая заявка, частичное
   исполнение и изменившееся состояние не резервируют новый ордер.
4. `RSCO_REENTRY_READY`: в `task.reentry` и `task.key` находится одно
   подготовленное намерение. Для BUY цена = уровень закрывшего SL +
   дистанция; для SELL минус дистанция. Собственный SL нового STOP —
   подтверждённый уровень закрывшего SL. Прежний встречный STOP неизменен.
   Подтверждённый стоп поддержки записан отдельно, не увеличивая количество
   полных SL или текущую ступень размера. Повторный вызов не выдаёт заявку.

При подключении исполнитель должен один раз перепроверить точное старое
состояние ордера непосредственно перед отправкой; более ранний снимок
не гарантирует, что ордер всё ещё работает у брокера. Полный гэп, отсутствие
прежнего встречного ордера на последней ступени, подтверждение нового
созданного тикета, два возможных последующих исполнения и обновление
владельца после них здесь не подключаются.

Проверка из корня: `python3 design/recovery-ea/execution/test_support_close_owner_compat.py`.
Стенд C++ использует настоящую логику диапазона, учёта, ключей и нормализации
рабочей строки; ввод готового ответа и его файловая доставка имитируются.
MetaEditor и терминал не запускались.
