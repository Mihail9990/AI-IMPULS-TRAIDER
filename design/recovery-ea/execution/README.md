# Подтверждение первого SL и встречного триггера

`RecoveryAdoptionGate.mqh` — чистая проверка результата ручного подхвата, без
торговых вызовов. Одного ответа об отправке недостаточно. Подхват подтверждён,
только если EA сверки видит ту же позицию с ожидаемым SL и неизменным TP и
тот же рабочий встречный стоп-ордер с ожидаемым направлением, ценой, SL и
остатком объёма. Цена триггера совпадает с ожидаемым SL позиции.

План передачи в проверку:

1. До отправки сохранить намерение с привязкой к счёту, серверу, символу и
   поколению контекста. Если у позиции уже есть SL, его не отправлять на
   модификацию. Если SL нет, запланировать SL и встречный триггер отдельно;
   не считать эти операции атомарными.
2. Привязать точный тикет встречного ордера к намерению. Не брать похожий
   ордер по цене, объёму, стороне или магическому числу. Неизвестный тикет
   оставляет итог неопределённым до отдельной сверки.
3. Получить доказательство по новому запросу после отправки обеих операций
   (или единственной заявки, если стоп уже был). Адаптер должен проверить
   nonce, оба запуска советников, счёт, сервер, символ и поколение, затем
   присвоить внутренний `scope`. Привязка не является хешем счёта или
   идентификатором торгового инструмента. Сравнить порядок по верифицированной
   последовательности из текущего запуска, без сравнения часов.
4. Цены нормализовать в целое число тиков, объёмы в целое число шагов по
   контракту символа. Не округлять сомнительное значение до ожидаемого.
   Признак `coherent` ставить только для валидированного ответа, относящегося
   к одной сверке. Это не обещание атомарного брокерского снимка или того, что
   брокерское состояние не изменится после наблюдения.

Исчезновение позиции или ордера, либо уже исполненный триггер не доказывают,
что действие не выполнено. Это `RA_UNRESOLVED` и сверка истории по конкретным
тикетам; не повторная отправка. `RA_CONFLICT` означает несовместимость данных
с намерением, а не право на повтор, перенос SL, рыночный вход или отмену.
`RA_CONFIRMED` принимает только случай, когда обе части подтверждены до
перехода в обычное сопровождение; не трактовать как сигнал отправить ордер.
Для гонки с исполнением необходим отдельный переход по доказательству из
истории, а не синтез видимости ордера в текущих данных.

Проверка C++: `g++ -std=c++17 -Wall -Wextra -Werror -pedantic test_adoption_gate.cpp -o /tmp/recovery-adopt-test && /tmp/recovery-adopt-test`.
Она проверяет алгоритм, но не заменяет MetaEditor/MT5. Связь с транспортом,
сохранение намерений, нормализация и брокерская сторона пока не подключены.

`RecoveryInventoryRequest.mqh` формирует терминальный запрос формата V1
для `../verifier/RecoveryVerifier.mq5`, без Python в канале между EA. Он не
создаёт торговых запросов и пока не вызван из торгового EA. Положительный ответ
функции означает только публикацию файла запроса, не получение снимка и тем
более не подтверждение эффекта на счёте.
