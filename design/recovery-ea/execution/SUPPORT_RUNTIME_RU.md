# Один перенос SL поддержки

Для диапазона RR_ACTIVE с независимо подтверждённым встречным ордером
владелец передаёт `RecoverySupportRuntimeTimer` состояние из своего
активного сеанса, точный контекст сверщика и ID/эпоху отдельного наблюдателя.
Использовать одну RAM-структуру на диапазон. При смене связанной
позиции прежняя подписка, если она ещё ждёт, снимается один раз; для нового
входа формируются новые уникальные nonce из счётчика того же владельца.
Главный таймер сначала обрабатывает подтверждённое обычное исполнение,
затем вызывает сопровождение для текущего диапазона.

Подписка привязана к точным позиции, фактическому входу и объёму. Один
настроенный порог, цель — фактический вход. Модуль не меняет встречный
ордер. Подтягивание не отправляется, если SL отсутствует или уже находится
на входе либо в более выгодной точке; используется действующий редьюсер
«только улучшение имеющегося SL». Как и до этой подписки, отсутствие SL
не мешает независимой встречной цепочке.

Порог даёт одну асинхронную попытку точного переноса SL. Этот вызов не
означает подтверждение. Таймер ждёт, пока локальное чтение увидит у этой
позиции целевой SL, и только тогда один раз запрашивает независимый
снимок, чтобы не потребить одноразовый ответ до применения изменения.
Надёжное состояние отражает только совпавший ответ точной позиции
(тикет, ID, цена, сторона, объём, magic и TP). Нет повторов торгового
запроса под тем же входом, задержек/возрастных ограничений или
восстановления прежнего сеанса.

`python execution/test_support_runtime_compat.py -v` имитирует терминал
и шлюз и проверяет однократную подписку, отправку, раздельное подтверждение,
смену позиции и неизменность встречного ордера. Нативная компиляция,
веб-интерфейс и торговый терминал не запускались.
