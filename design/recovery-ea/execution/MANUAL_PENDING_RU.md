# Подхват выставленного пользователем STOP-ордера

`RecoveryManualPendingOwner` хранит ожидание только в текущем сеансе.
Все вызовы принимают флаг `arm_pending`; владелец графика устанавливает
его только при подтверждённом режиме `REC_CONTROL_PENDING_WAIT`, а не
при ожидании рыночной позиции. Отмена ожидания прекращает наблюдение:
этот модуль не отменяет ордер MT5 и не пытается отозвать уже отправленное
изменение SL.

1. `RecoveryPrepareManualPending` связывает ровно один подходящий
   Buy/Sell Stop из полной независимо полученной описи по точному
   тикету. Если есть несколько кандидатов и пользователь не выбрал
   конкретный тикет, ничего не меняется. Допускаются
   только ещё не исполнявшиеся
   текущие рабочие STOP с исходным полным объёмом; частичный остаток
   для подхвата не подходит. Допустимы только ручные источники
   CLIENT/MOBILE/WEB с magic=0. Limit, Stop Limit и сторонние EA-ордера
   не обрабатываются.
2. Существующий SL и TP остаются как есть, запрос не нужен.
   Для ордера без SL целевая цена считается от заданной цены триггера
   на настроенную дистанцию. `RecoveryAttemptManualPendingSL` может
   только один раз попытаться изменить этот тикет. Запрос сохраняет
   цену, TP, срок действия и не задаёт новый объём. Перед OrderCheck
   и затем сразу перед отправкой перечитываются точные текущие
   свойства. Запоздалый запрос не отправляется, если ордер уже
   исполнился или его свойства изменились. Установка, замена,
   отмена или повторная отправка заявки не выполняются.
3. Если уже независимо замеченный тикет исполнился до первой
   локальной проверки, точная локальная история по неизменённым
   исходным условиям может сохранить его распознанным без торгового
   запроса. Это лишь подсказка для отдельной проверки исполнения,
   не факт позиции. Если исходная независимая опись не видела ордер
   до исполнения, этот режим не угадывает неизвестный тикет.
4. `RecoveryConfirmManualPendingSL` отмечает ожидаемый SL только
   по новой полной описи того же сеанса и точного тикета, с неизменными
   исходными параметрами. Ответ отправки сам по себе не считается
   доказательством. Сопровождение после исполнения — отдельный
   обработчик точной истории и описи, учитывающий фактический вход.

Формат изменения заявки и сохранение её срока основаны на [справке MetaQuotes
об изменении отложенных ордеров](https://www.mql5.com/en/book/automation/experts/experts_modify_order).
Офлайн-тест `python execution/test_manual_pending_compat.py -v` использует
реальный парсер описи, C++17/UBSan и подставной транспорт. Нативный
MetaEditor, VPS и реальный счёт не затрагивались.
