# Обычный встречный ордер: события основного EA

Для рабочего диапазона владелец фиксирует точный тикет встречного ордера.
`RecoveryReserveOwnerEvidence` формирует связанный запрос сверки в текущем
сеансе, `RecoveryOrdinaryEventBind` привязывает его к диапазону. Для ещё не
подтверждённой пары точный тикет берётся из записи того же намерения, ключ
которого создаёт `RecoveryBuildSessionIntentKey`.

`RecoveryOrdinaryOnTrade` записывает событие по тикету и ничего не отправляет.
`RecoveryOrdinaryOnTimer` начинает сверку. Если событие пропущено, таймер
может только прочитать историю уже известного тикета; этот результат также
не заменяет независимую сверку. После неё формируется следующий встречный
ордер на настроенном расстоянии от фактического входа. Нет действительного подтверждения — нет новой
заявки. Таймер не вводит задержку по часам, повторные заявки или новые режимы.

Функции не подключены к готовому основному советнику и не реализуют начало
работы из панели, другие сценарии сопровождения или сборку. Тесты используют
имитацию терминала. Сеанс всегда начинается пустым; при остановке уже
принятые брокером ордера и SL остаются на счёте.
