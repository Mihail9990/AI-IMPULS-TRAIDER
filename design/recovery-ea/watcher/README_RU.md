# RECOVERY: третий советник наблюдения за ценой

`RecoveryPriceWatcher.mq5` читает позицию и котировку в MT5. Он не ставит
и не меняет ордера или SL. Подключается на третьем графике того же символа,
отдельно от торгового советника и советника подтверждения эффектов. Он
сообщает торговому советнику только подсказку о достигнутом пороге.

- Позиция должна совпасть по счёту, серверу, символу, постоянному ID, текущему
  тикету, направлению и фактической цене входа. Она читается до и после
  наблюдения котировки. BUY сравнивается с Bid, SELL с Ask.
- Оба порога передаёт торговый советник из настройки диапазона: значения
  по умолчанию 0.25 и 0.40, проверяется `0 < первый < второй`. Наблюдатель
  не рассчитывает цену нового SL и не подтверждает его перенос.
- Ступень 0 — оба порога не достигнуты; 1 — достигнут первый; 2 — достигнут
  второй. Если позицию или котировку не удалось точно прочитать, сигнал
  недоступен. Не использовать это как разрешение повторить торговый запрос.
- Торговый EA повторно проверяет текущую позицию и допустимость перехода;
  ответ наблюдателя не считается ни заявкой, ни подтверждением брокера.

## Локальный протокол

В песочнице выбранного MT5 (`MQL5/Files/RECOVERY_PRICE`) торговый советник
публикует `<nonce>.watch`, читает `<nonce>.quote`. Однострочный UTF-8 TSV
со строгой привязкой ко всем полям, ответ LF:

```text
RECOVERY_PRICE_REQUEST_V1 nonce executor_epoch watcher_epoch generation login server symbol position_id live_ticket side actual_entry first_advance second_advance watcher_chart END
RECOVERY_PRICE_V1 nonce executor_epoch watcher_epoch generation login server symbol watcher_chart sequence position_id live_ticket side actual_entry first_advance second_advance observed_or_unavailable stage selected_quote END
```

Числовые поля цен и расстояний — канонический `DoubleToString(x,16)`, ID —
целые десятичные строки. У недоступного наблюдения ступень −1 и котировка
0. Запрос и ответ create-only; новый запуск требует новые идентификаторы
запуска, новое наблюдение — свежий nonce. Читатель сравнивает последовательность
только в рамках одного запуска. Это защита от перепутанного ответа, а не
возраст котировки, контроль часов или блокировка торговой команды.
## Подписка на следующий порог (V2)

Для ожидания нужной ступени торговый EA публикует `<nonce>.follow` через
`RecoveryPriceFollow(scope, desired_stage, publisher_tag)`. При достижении
этой или более высокой ступени он читает `<nonce>.peak` через
`RecoveryPricePeakRead(scope, after_sequence, desired_stage, out)`.
Оба порога и запрошенная ступень 1 или 2 связываются с тем же точным контекстом.

```text
RECOVERY_PRICE_FOLLOW_V2 nonce executor_epoch watcher_epoch generation login server symbol position_id live_ticket side actual_entry first_advance second_advance desired_stage watcher_chart END
RECOVERY_PRICE_PEAK_V2 nonce executor_epoch watcher_epoch generation login server symbol watcher_chart sequence position_id live_ticket side actual_entry first_advance second_advance desired_stage observed reached_stage selected_quote END
```

Одновременно активно до четырёх подписок. Таймер принимает их из файловой
очереди; пока подписка не принята, пиков не копит. После принятия `OnTick`
накапливает наиболее благоприятную котировку и ступень. Возврат цены, пробел
в котировках и неудачная запись не стирают собранный максимум в памяти.
Таймер пытается опубликовать ответ без замены, только достигнув запрошенной
ступени. Возможны пропуски событий MT5 при загруженной очереди: это не
воспроизведение всех тиков и не основание действовать по устаревшей позиции.
Перед расчётом и перемещением SL торговый советник проверяет живое состояние
заново. Наблюдение не сохраняется сквозь перезапуск EA; после запуска выдаётся
новый идентификатор запуска и новый nonce, старый сигнал не принимается.

Для отмены принятой либо ожидающей подписки торговый EA публикует
`<nonce>.drop` с тем же точным содержимым через `RecoveryPriceDrop`.
Изменённый контекст не отменяет чужую подписку. У достигнутой ступени ответ
не переписывается; запрос, ответ и отметку отмены обслуживает владелец
торгового цикла только после разрешения связанных операций. Не переиспользовать
nonce. V1 `.watch/.quote` остаётся диагностическим снимком без накопления.

Проверки на хосте: `python -m unittest -v test_price_watcher_compat.py` в
каталоге `watcher/`. Они проверяют обе ступени, сохранение пика при откате,
привязку V1/V2 и отсутствие торговых вызовов. Это не компиляция MetaEditor,
не проверка файлового обмена или очереди событий внутри MT5 и не запуск
на VPS. Подключение V2 к рабочему циклу и проверка в MT5 остаются отдельными
этапами.
