# Сохранение единственного порога RECOVERY

Серверный адаптер для новой ветки без импорта MT5 или отправки заявок.
`GET /api/recovery/ea/support-settings` возвращает ровно `revision`,
`editable` и `support_threshold`; `PUT` принимает ровно `revision`
и `support_threshold`. Старые параметры первой ступени и любые другие
поля в запросе отклоняются. Использовать действующую защищённую сессию
и проверку CSRF. При 409 обновить форму, не повторять запись автоматически.

Профиль сохраняет одну настройку в приватном файле отдельно от очереди
торговых команд. Если у этого профиля уже есть файл настроек V1, его
`support_second` становится единственным порогом; остальные поля первой
ступени игнорируются. Само чтение старый файл не изменяет. При обычном
сохранении изменённого значения файл атомарно заменяется на V2. Другие файлы
предпочтений, журнал и состояние стратегического цикла не читаются и не
изменяются.

## Контракт владельца состояния

До монтажа маршрута нужен **один процесс-владелец резервирования**:
`SupportStore(private_path, owner_lock, observe)`, где `owner_lock` —
общий `RLock`, а `observe` возвращает настоящее состояние поколения
и точный шаг цены. При резервировании внутри `locked_next_generation()`
значение переводится в тики и присваивается тому же неизменяемому поколению.
Действующее поколение не переписывается. Нельзя считать read-only
`Channel.state()` достаточным доказательством idle или заменой общего замка.
Если единственный владелец EA, необходим его протокол согласования:
Python-замок не делает отдельный EA атомарным с веб-сервером.

Из данного каталога: `python -m unittest -v test_support_settings test_support_runtime`
и `node --test test_support_controls.mjs`. Фрагмент формы и опциональный
HTTP-роутер не монтируются автоматически; эти проверки не запускают MT5.
