## Поведение

Новые обычные AUTO-циклы обоих движков используют один STOP по закрытой M1.
Старт в середине минуты ждёт закрытия этой минуты. Для BUY цена Close + distance,
для SELL Close − distance. Doji сохраняет ожидающий ордер, а без него продолжает ожидание.
Свечи того же направления не передвигают ордер. Противоположная свеча фиксируется
в SQLite вместе с запросом замены. После отправки отмены повторно читаются брокерские
факты; одного ACK, исчезновения ордера или локального предположения недостаточно.
Fill до/во время отмены сохраняет позицию и её защиту. UNKNOWN не повторяется.

Начальный STOP не догоняет цену рынком. Недопустимый, пересечённый или слишком близкий
уровень отклоняется с записью события и ожиданием следующей направленной M1.
BUY проверяется от Ask, SELL от Bid; exact tick и stop constraints сохраняются.
Направление, Close сигнала и последний обработанный candle ID сохраняются до отправки
ордера. Старые/неупорядоченные свечи не исполняются задним числом.

После завершения цикла по TP — свежая M1; настройка cooldown задаёт дополнительное ожидание.
Новый конфиг InteractiveController имеет cooldown 0. Сохранённая пауза, включая прежние 60,
сохраняется. При ненулевой паузе после её окончания ожидается следующее закрытие свечи.
Стоп отменяет начальный pending, а при уже исполненной позиции сохраняет finish-cycle.
Возобновление отменённого начального входа снова ждёт свежую M1.

SL переводит в прежний recovery. Для legacy сохранены размер, monetary target,
ступенчатая защита, tolerance и дальнейшие ветви. Центр первой recovery вычисляется
`initial_trigger − sign * BRANCH1_RANGE`: прежний симметричный алгоритм повторно использует
точный исходный уровень со стороны входа. Расстояние recovery SL остаётся прежним,
а не подменяется новым начальным SL. Fixed по-прежнему учитывает подтверждённый net и N частей.
Существующие активные циклы без метки новой стратегии завершаются по прежней логике.
SEMI и математические модули recovery не переписаны. Никаких изменений paper-анализатора.

## Миграция параметров

| Новый ключ | Новая установка | Источник при отсутствии ключа в сохранённых настройках |
|---|---:|---|
| INITIAL_ENTRY_DISTANCE | 1.00 | BRANCH1_RANGE |
| INITIAL_SL_DISTANCE | 4.00 | BRANCH1_SL_DISTANCE |
| INITIAL_TP_DISTANCE | 0.25 | BASE_TP_DISTANCE |
| CYCLE_COOLDOWN_SECONDS | 0 | Сохранённое значение без изменения |

Старые пользовательские значения, даже если они совпадали с прежними defaults,
не заменяются молча. Поэтому обновление старой базы **не обязательно даст 1 / 4 / 0.25**:
нужные значения видны и редактируются в панели до нового цикла. Новые ключи независимы
от параметров recovery и SEMI. Активный цикл использует свой сохранённый снимок настроек.
В журнале команд старый cursor мигрирует в нейтральный command_offset; отложенные
сообщения прежнего транспорта больше не принимаются и не исполняются.

## Веб-панель

Удалены polling/worker, библиотека credentials и шаблон Telegram, требования к token/chat/user,
создание credentials и установочный диалог. Старые локальные файлы секретов не удаляются.
`requests` сохранён: он нужен независимой проверке UTC, а не сообщениям.

Панель использует прежний owner/controller и durable ActionGateway. HTTP worker не работает
с MT5/SQLite напрямую. Есть старт/стоп, AUTO/SEMI, legacy/fixed, все настройки, ручные цены/
расстояния SEMI, SL/TP, удаление ордера, закрытие позиции, график, события, phase/cycle/debt
и действия сверки. Ручное перемещение начального AUTO-уровня отклоняется до отмены:
его определяют свечи; ручные входы задаются в SEMI. Удаление AUTO-ордера останавливает
новые входы до явного старта. Изменения и опасные действия требуют подтверждения.

Существующий reset имеет разные правила: **FIXED сохраняет долг**, **LEGACY списывает
остаток цели после подтверждённой ручной сверки**. Панель показывает предупреждение
для активного движка, а не выбранного на следующий цикл. Эта историческая семантика
не изменялась; автоматический reset и скрытое списание не добавлены.

Вход требует заданного оператором пароля. В текущей версии `web.password` допускает минимум 5 символов только для локального VPS, для внешнего HTTPS/proxy требуется 32. Готового пароля нет.
Сессии в памяти, срок 1 час; HttpOnly/SameSite, Origin/Host/custom-header проверки,
rate limit, bounded workers/body/queue и durable request IDs. Повтор одного id не исполняется
вторично; неопределённый receipt не даёт права повторить торговый запрос. Журнал UI ограничен.

Сервер по умолчанию 127.0.0.1:8765. Для HTTPS proxy задаётся точный public_origin;
тогда cookie Secure. Proxy сохраняет Origin и переписывает upstream Host. Конфигурация
сети, домена, сертификата, Windows-службы и разрешений торговли остаётся вне этой правки.

## Исправление проверки ввода перед выпуском

Неверный текст/число/ключ настройки, недопустимый режим или модуль, неверная ручная цена
и очевидно недопустимые reset/resume теперь дают типизированный отказ `REJECTED` до
выполнения соответствующего действия. UI снимает ожидание запроса: ввод можно исправить,
после чего сохранить настройки или нажать Стоп. Проверки формата выполняются до вызова
торговых guards и исполнителей; точные ограничения брокера — до сохранения настроек.

Общего преобразования ValueError в отказ нет. Исключение после сохранения/отправки остаётся
`UNKNOWN`, durable receipt не переигрывается. Панель показывает ID, состояние ожидания
и инструкцию сверить журнал/брокера на VPS; перезагрузка и повторный вход не подтверждают
исполнение и не снимают такую блокировку.

Регрессия воспроизведена через настоящий ActionGateway в Chromium: значение `bad` →
REJECTED без изменения параметров/торговых команд → перезагрузка и повторный вход →
исправленное значение → Стоп. Отдельно проверена поздняя ошибка после эффекта: UNKNOWN
остаётся после перезагрузки и не исполняется повторно. Полный offline suite: 522 теста, OK.
