# Архив правил корзины — 31 октября 2026

**Историческое описание v1. Штатный запуск и paper теперь используют v2.**
Актуальные правила, обязательный TP1 и ограничения: [RECOVERY v2](RECOVERY_V2_PENDING_RU.md).
Ниже сохранена прежняя схема для сверки старых активных циклов.

Штатный сервис `tradfi.runtime` использует `BasketController`. Старые математические
ветви legacy/fixed и SEMI исключены из маршрута исполнения и новой панели. Их исходники
и тесты оставлены как архив и для совместимости инфраструктуры; переключателя на них нет.
Отдельный бумажный симулятор и вложенные ZIP анализаторов не изменялись.

## Цикл

Старт ждёт закрытия текущей M1. Close > Open: один BUY STOP по Close + расстояние;
Close < Open: SELL STOP по Close − расстояние. Doji ничего не меняет. Свечи того же
направления не двигают STOP. Противоположная свеча заменяет его только после сверки
отмены и отсутствия исполнения. При исполнении во время отмены действует позиция.
Старые/повторные свечи не обрабатываются; якорь и последний ID сохраняются в SQLite.
Пересечённый уровень не догоняется MARKET.

Пример: BUY 4000, SL 3997, TP 4000.25. После подтверждения BUY выставляются шесть SELL
STOP 3997 по 0.01 с SL 3998.50. Начальный TP отменяет их и ждёт подтверждения отсутствия
позиций/ордеров. При SL начальной позиции принимается фактический SELL-баскет. Если он
получает SL, один раз фиксируются BUY STOP 3999.50 и SELL STOP 3996.00. Последующие
автоматические повторные входы используют эти уровни без нового расширения. SELL-старт
зеркален. При исполнении одной стороны встречные ордера отменяются.

SL и STOP у брокера не атомарны: BUY закрывается/SELL STOP срабатывает по Bid,
SELL закрывается/BUY STOP срабатывает по Ask. Одновременная начальная и восстановительная
позиции, исполнение обеих сторон OCO, частичный объём одного билета, неизвестные факты
или отказ части корзины останавливают автоматизацию для сверки. Недостающие билеты
не добираются MARKET. Защита уже открытых позиций сохраняется.

## Долг и TP

Долг = max(0, −подтверждённый суммарный результат цикла с комиссиями, swap и fee),
в валюте счёта. Долг не равен расстоянию в цене. При равном входе/объёме q, числе n,
стоимости единицы движения C и долге D шаг δ = D / (C × q × n(n+1)/2).
Цели: entry ± kδ, k=1..n. К долгу не добавляется исходная цель прибыли.

Шаг округляется вверх к тику; все TP проверяются через расчёт прибыли брокера.
При разных фактических входах используется общий наиболее выгодный вход как якорь,
с учётом прибыли каждого реального билета. Фактический SL при гэпе не расширяется.
Лестница фиксируется после сверки входов; отдельные TP не перераспределяют оставшиеся цели.
Если часть билетов уже закрылась до окончательной сверки, сохраняются поданные цели,
а фактический остаток долга виден и не списывается. Новая корзина пересчитывает цели.

Нормированный пример q=.01, C=1: начальный убыток 3 даёт D=.03, шаг 1/7.
SL всех шести на 1.5 даёт D=.12; два первых TP, затем SL четырёх дают
D=.0857142857 до округления к тику. В тестах XAU C=100 с тиком .01 фактическое
соответствующее значение после двух TP и четырёх SL — 8.55 валюты счёта.

Будущая комиссия заранее неизвестна. COST_RESERVE — явный запас, по умолчанию 0.
При оставшемся долге после всех TP цикл не считается завершённым. При избыточной
прибыли на гэпе остаточные позиции закрываются отдельными полными CLOSE, pending
отменяются, результаты подтверждаются; убыток этой очистки может восстановить долг.
Новый цикл начинается только при покрытом долге и отсутствии позиций, ордеров и
неопределённых обязательств, затем ждёт свежую M1. Нет гарантии прибыльности/покрытия
при ограничениях брокера или проскальзывании.

## Параметры

Все расстояния — единицы цены, не количество тиков.

| Ключ | Новая установка | Применение |
|---|---:|---|
| INITIAL_SIZE | 0.09 | следующая начальная позиция |
| INITIAL_ENTRY_DISTANCE | 1.00 | начальный STOP от закрытия M1 |
| INITIAL_SL_DISTANCE | 3.00 | начальный SL и противоположная корзина на нём |
| INITIAL_TP_DISTANCE | 0.25 | начальный TP |
| BASKET_COUNT | 6 | число билетов следующей корзины, 1–20 |
| TICKET_SIZE | 0.01 | объём каждого следующего билета |
| RECOVERY_SL_DISTANCE | 1.50 | фиксированный SL корзины |
| EXPANSION_DISTANCE | 1.00 | расширение один раз, если ещё не произошло |
| COST_RESERVE | 0.00 | явный денежный запас для будущих расходов |
| TP_STEP_MULTIPLIER | 1.00 | множитель шага TP, не меньше 1 |
| CYCLE_COOLDOWN_SECONDS | 0 | дополнительная пауза; затем свежая M1 |

Требуется hedging с независимыми билетами, допустимыми min/step/max объёмами.
Если брокер не разрешает .01, Старт отклоняется, объём не округляется вверх.
Цена должна соответствовать tick/stops/freeze; недопустимая правка отвергается.

## Активные правки и телефон

Короткое движение панорамирует график; удержание 500 мс открывает предпросмотр уровня.
Есть кнопки изменения без жестов. Подтверждение отправляет текущие cycle ID, revision,
старые уровни и ID ордеров. Повторный запрос идемпотентен; устаревшая вкладка получает
конфликт/отказ. SL изменяется для всей группы; TP — для конкретного билета.
Уменьшение TP может оставить долг: панель показывает прогноз и дефицит.
Ручные изменения замороженных триггеров сохраняются как новые якоря.

Число/объём не наращивают и не сокращают открытые позиции; при замене ещё ожидающей
корзины новые значения действуют для новых билетов. Изменение расстояния расширения
не передвигает уже зафиксированные якоря. Изменение SL не тянет его автоматически
за ценой. Явное изменение резерва/множителя пересчитывает лестницу оставшихся билетов.

Перед заменой pending сначала подтверждается отмена. Исполнение/закрытие во время
этого процесса прерывает правку и требует сверки. Множественные изменения SL/TP не
атомарны: частичный отказ сохраняет реальные успешные изменения, панель показывает
брокерское состояние, автоматизация останавливается. Неизвестный результат не
повторяется. После UNKNOWN браузер хранит ID запроса и блокирует новые команды до
сверки receipt; перезагрузка не снимает блок. Не следует удалять это состояние для
повторной отправки: нужна проверка журнала и брокера. Проверенные ошибки входных
параметров возвращают REJECTED и не блокируют следующую правку или Стоп.

Стоп прекращает новые входы, отменяет ожидающие ордера и оставляет защиту открытых
позиций; не является массовым закрытием. Ручная сверка возможна только после
подтверждения отсутствия обязательств; остаток долга переносится, не списывается.

## Миграция и запуск

Сделайте отдельную резервную копию SQLite и локальной конфигурации до обновления.
Если есть старый активный legacy/fixed цикл или фиксированный перенос долга,
новая версия сохраняет исходный снимок, блокирует запуск и не переинтерпретирует долг.
Такой цикл следует сверить/завершить предыдущей версией; автоматической миграции нет.
Не удаляйте базу для обхода блокировки.

Для старой плоской базы без долга сохраняются INITIAL_SIZE, INITIAL_ENTRY_DISTANCE,
INITIAL_TP_DISTANCE и CYCLE_COOLDOWN_SECONDS. Старый SL и legacy/fixed recovery
параметры НЕ переносятся: новая стратегия получает SL3, корзину6×.01, SL1.5,
расширение1. Старые ключи остаются в базе для истории. Уже созданные basket_settings
повторным запуском не перезаписываются. До Старт проверьте новые значения в панели.

Авторизация, loopback по умолчанию, Origin/CSRF, HttpOnly/SameSite, идемпотентные
receipt, контроль 24 часов/времени и ownership сохранены. Telegram отсутствует.
HTTPS reverse proxy и Android-доступ на VPS настраиваются отдельно, как описано в
README. Этот пакет ничего не устанавливает и не запускает на VPS; реальные сделки,
MT5-соединение и публикация панели не выполнялись.

## Время на 2 ноября 2026

По [календарю Bybit](https://www.bybit.com/en/help-center/article/How-to-Get-Started-with-CFD-Trading)
серверное отображение переходит UTC+3 → UTC+2 1 ноября 2026 в 02:00 UTC.
Текущий лёгкий профиль уже содержит этот переход. Для тестов 2 ноября никаких
ручных «−1 час», новых переключателей или подмены даты не добавлено. Старые
летние метки сохраняют своё летнее правило; реальные UTC epoch не сдвигаются
для настройки зимнего отображения. M1 и 24 часа цикла считаются в UTC.

**Обновление:** описание UTC без смещения ниже относится к исходному профилю 0.
Текущий сервис поддерживает явный фиксированный профиль без сезонных переходов.
См. [Фиксированное время MT5](FIXED_MT5_TIME_RU.md).

Важно различать часы сервера и формат данных SDK: официальная документация
[MT5 bars](https://www.mql5.com/en/docs/python_metatrader5/mt5copyratesfrom_py) и
[MT5 ticks](https://www.mql5.com/en/docs/python_metatrader5/mt5copyticksfrom_py)
описывает UTC. Календарь отображения Bybit не доказывает сдвиг epoch SDK.
Штатный сервис теперь содержит `NativeUTCVerifier`. Он на owner-потоке читает
текущий tick и две M1 без торговых операций, сравнивает их с независимо проверенным
UTC и применяет официальный UTC-контракт SDK: epoch НЕ сдвигается на 2 или 3 часа.
Проверяются свежесть (до 5 секунд), согласованность time/time_msc, минутная сетка,
предыдущая/текущая M1 и длительность чтения (до 2 секунд). Смена минуты во время
чтения допускает временный отказ и повторную проверку, не угадывание.
Календарь UTC+2 относится только к серверному отображению. Исторические времена
сделок по-прежнему не объявляются глобально проверенными; учёт опирается на ID.

Статусы: `MT5_UTC_WAIT_REFERENCE` — ещё нет свежей независимой проверки UTC;
`MT5_UTC_WAIT_FRESH_DATA` — нет свежего тика/согласованной M1 (в том числе закрытый
рынок); `MT5_UTC_CONTRACT_MISMATCH` — метки не соответствуют контракту UTC,
например wall-time +2 часа. Смещение не угадывается и не исправляется.
После получения свежих данных и независимой проверки нажмите «Проверить время»:
сохранённая блокировка снимается только явной успешной перепроверкой. Никакой
доработки пользователем или установки verifier не требуется. Расхождение часов
не создаёт команд закрытия позиций и не снимает SL/TP; новые входы блокируются,
ожидающие ордера могут отменяться по существующим правилам защиты.

```text
python tools/check_mt5_utc.py --config service.json
```

Этот диагностический путь принудительно выключает торговлю, не открывает SQLite,
не меняет часы и не запускает веб-сервис. Код выхода 0 и `UTC_VERIFIED` означают
успешную текущую проверку; код 2 — ожидание данных или необходимость разбора.
На закрытом рынке это не ошибка установки. Исторический `--inspect` и старый
90-секундный probe оставлены для аудита; для текущего UTC-контракта используйте
именно `check_mt5_utc.py`. Автоматическое вычитание +2h по старому wall-профилю
не применяется в штатном runtime. Торговые сессии XAUUSD.s не зашиты в код.

Офлайн проверены UTC(+0), отказ wall(+2), stale/unavailable M1/tick, истёкшая
UTC-проверка, медленное чтение, отсутствие вызовов MT5 из HTTPS-worker, полный
штатный путь ожидание → проверка → M1 → STOP, сохранение открытой позиции и
SL/TP при расхождении часов, диагностическая команда без торговых/DB эффектов,
зимнее отображение, старт посреди M1 и ровно 86400 секунд.
