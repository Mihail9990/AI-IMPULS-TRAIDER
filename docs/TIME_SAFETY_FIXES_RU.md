## 1. P1: скачок часов и сопровождение позиции

Запрет новых STOP/MARKET отделён от CANCEL/MODIFY при MANUAL из-за скачка часов
или истечения срока. Сам MANUAL и срок ветки не снимаются. Сопровождение принимает
подтверждённое исполнение, отменяет противоположный ордер и допускает защитные
изменения с прежними проверками позиции, цены, stop/freeze и владения.
Для проверки пригодности котировки допускается только свежая монотонная проекция
последнего успешного независимого UTC-измерения; часы ОС не меняются. Свеча native
профиля проверяется относительно того же эталона. Ошибка принятия позиции не
вызывает обращение к отсутствующей позиции; broker SL/TP остаются.

Регрессии: backward clock в injected и native профилях, OCO, MODIFY, рестарт,
expiry+неуспешный расчёт цели; прежние тесты срока сохранены и обновлены на
разрешённое защитное сопровождение после expiry.

## 2. P1: неподтверждённые timestamps MT5 и reconcile

Семантика проверяется до преобразования tick/candle timestamps. При отсутствии
доказательства timestamps остаются display-only: quote UTC отсутствует, candle id=0.
Непригодная котировка не уничтожает подтверждённые сведения об ордерах и позициях;
согласованность снимка, identity и per-obligation evidence продолжают проверяться.
`require_fresh=True` и price-sensitive мутации сохраняют строгие требования.
При отсутствии пригодной котировки новый MODIFY не планируется по устаревшей цене.

Регрессии: native profile с нулевыми, отрицательными, NaN и огромными raw timestamps,
собственные открытые позиции/ордера сохраняются; explicit fresh read отказывает.
`MT5_TIMESTAMP_SEMANTICS_UNVERIFIED` не отключён, production verifier по умолчанию
по-прежнему не подтверждает семантику.

## 3. P1: уже выставленные pending при time_block

READY-входы помечаются never_sent, собственные выставленные pending получают
журналируемые CANCEL. Проверки владения, счёта, конфликтов, повторная подготовка
запроса и broker order_check сохранены. Ticket-only REMOVE при неподтверждённых
timestamps допустим только когда не требуется ценовая проверка freeze level;
непроверенное время при этом не объявляется UTC. Для ненулевого freeze level
проверка времени котировки остаётся обязательной.

Fill/cancel race сверяется по evidence: появившаяся позиция принимается в
сопровождение, исходные SL/TP сохраняются; обе исполненные стороны требуют
ручной сверки. UNKNOWN не повторяется. После положительно подтверждённой отмены
всей пары, flat и отсутствия незавершённых операций сохраняется NEXT_PAIR с latch.
Периодическое успешное измерение не открывает новую пару; нужен явный /resume_time.

Регрессии: отмена двух ордеров, native unverified и рестарт, foreign ownership,
исполнение в order_check отмены, UNKNOWN после order_send, READY-входы,
ненулевой freeze level, явное возобновление после подтверждённой отмены.

## 4. P1: точно не отправлено против неизвестного исхода

Исключения до вызова order_send, включая финальную проверку после записи may_send,
сохраняются как REJECTED + never_sent с send_started=False. Transient отказ
дополнительно отмечается retryable_not_sent. Новая защитная операция разрешена
только при таком durable доказательстве и успешной свежей подготовке контекста;
используется новый ID. Повторные stale-наблюдения не расходуют лимит broker
отказов и не создают бесконечные новые CANCEL-intents. Для MODIFY сохраняется
связь замещённого intent. После вызова order_send неопределённость остаётся UNKNOWN;
после потери durable записи неотправки автоматический replay запрещён.

Регрессии: expiry+stale quote, пять повторных stale ticks без новых отправок,
рестарт, восстановление свежей котировки, сбой сохранения not_sent,
TimeoutError после фактического вызова order_send, transient неотправленный MODIFY.

## 5. P2: HTTP UTC блокировал execution loop

Controller refresh и /resume_time теперь только запускают фоновое измерение.
Работает не более одного daemon worker; зависший запрос не создаёт очередь потоков.
Worker изменяет отдельную копию измерителя, а owner thread публикует результат.
Окно проверки — 15 монотонных секунд; просроченный результат игнорируется и не
восстанавливает доверие. Исходные HTTP connect/read timeouts, три измерения,
RTT/offset/uncertainty и freshness=60 секунд сохранены. Поздний polling уже
завершённого результата оценивает время фактического завершения, затем freshness.

Перед публикацией нового anchor owner сохраняет обнаруженный скачок. Только
успешное свежее измерение конкретного явного /resume_time снимает time latch;
MANUAL, stop, сроки и reconciliation не сбрасываются. В процессе проверки latch
сохраняется. Рестарт теряет лишь process-local запрос resume и требует нового
явного запроса. Ошибка durable записи запроса/снятия latch не разрешает входы.

Регрессии: заблокированный HTTP не задерживает Telegram и полный controller.tick
в native runtime с doubles; один worker, timeout, поздний ответ, восстановление,
устаревание, failure/resume/restart, сбои записи latch. Тесты не вызывают реальный MT5.

## Ограничения и сохранённая семантика

- Неподтверждённые timestamps не разрешают новые входы. MODIFY требует пригодной
  котировки. При неподтверждённом времени и ненулевом freeze level CANCEL может
  остаться запрещён. Недоступность API, конфликты владения, freeze и UNKNOWN
  исключают гарантию снятия всех pending; такие исходы не объявляются успехом.
- Worker с зависшим транспортом нельзя принудительно уничтожить безопасно;
  ограничены число потоков, время доверия результату и работа основного цикла.
  До завершения зависшего worker новый запрос не запускается. Он не пишет SQLite
  и не вызывает MT5. Состояние broker SL/TP при сбоях не стирается.
- Семантика поздно замеченного SL **не изменена**: существующий код начинает
  новую ветку по времени обработки подтверждённого закрытия; при уже истёкшем
  сроке остаётся MANUAL. Неоднозначность времени сделки против времени наблюдения
  требует отдельного решения, не исправляется скрытно этим патчем.
- Реальная сеть, MT5, торговый сервис, реальные сделки, системные часы, другие
  стратегии и панель не использовались и не менялись. Push/PR/deploy и публикация
  среды не выполнялись. Готовность к реальной торговле не заявляется.
