# Пароль панели через Блокнот

После установки этой версии откройте «Настройки (Блокнот)».
Установщик добавит отсутствующее пустое поле `web.password`, сохранив остальные поля.
В существующем объекте `web` должно быть поле:

```json
"password": ""
```

Между кавычками впишите **свой** пароль и сохраните файл. Готового пароля в примере нет.
Не заменяйте весь service.json примером: логин, путь MT5, база и остальные настройки сохраняются.
Если сервис уже работает, новое значение применяется только при следующем запуске.
Изменение файла само по себе не перезапускает сервис и не запускает торговлю.

Для браузера внутри VPS (`127.0.0.1` или `::1`) разрешено от **5 символов**.
Для настроенного `web.public_origin`/внешнего прокси требуется от **32 символов**.
Слушать нелокальный интерфейс по-прежнему запрещено даже с длинным паролем.
Для IPv6 локальный URL — `http://[::1]:8765/`.

**Не публикуйте панель с коротким паролем через внешний прокси.** Проверка loopback
не может обнаружить все внешние прокси. Длинный уникальный пароль предпочтительнее.
Файл хранит пароль открытым текстом: его может прочитать имеющий доступ к файлу.
Не отправляйте файл/скриншот с паролем в чат и не добавляйте его в репозиторий.
Файловые права, firewall и сертификаты эта версия не меняет.

Если `TRADFI_WEB_PASSWORD` уже задана в окружении запуска, она имеет приоритет.
Даже пустая или короткая переменная приводит к ошибке, а не скрытому выбору другого пароля.
При её отсутствии используется `web.password`. Неправильный тип поля конфигурации
отклоняется даже при заданной переменной. `.env` автоматически не читается.
Пустое поле без переменной запрещает запуск с понятной инструкцией.

Дальше можно использовать прежнюю кнопку READ_ONLY; PowerShell для пароля не требуется.
Остальные требования остаются: точный положительный expected_login, путь терминала,
совпадение сервера/счёта, доступный XAUUSD.s и проверки времени/состояния.
Реальный запуск — отдельное действие, разрешения торговли пароль не меняет.

Пароль не возвращается в API состояния. Веб-логи остаются allowlist-проекцией;
старый SQLite export дополнительно рекурсивно скрывает поля password/token/secret/credentials.
Ошибки настройки не содержат введённого значения. Rate limit, сессии, Origin/CSRF,
HTTP-only cookie и защита от повторных торговых запросов сохранены.
