# Один файл для Windows VPS

Требуется Windows, Python **3.13 x64** с Tcl/Tk из python.org и установленный MT5.
Установщик использует стандартную библиотеку Python; Git, ручной ZIP и CMD не нужны.

1. В репозитории `Mihail9990/AI-IMPULS-TRAIDER` выбрать ветку `work`, открыть
   `install_tradfi.py`, нажать **Download raw file**. Сохранить именно `.py`, не HTML.
2. Открыть файл двойным щелчком либо «Открыть с помощью → Python 3.13».
   Появится окно «TradFi — установка и запуск». Если Tcl/Tk отсутствует,
   восстановить этот компонент официальным установщиком Python; загрузчик его сам не устанавливает.
3. Нажать **Установить / обновить**. В окне показываются репозиторий и SHA `work`.
   Скачивается архив именно этого SHA. Подготовка идёт в фоне, кнопки конфликтующих
   действий отключены. Дождаться сообщения об окончании, не закрывать окно во время операции.
4. Нажать **Настройки (Блокнот)**. Заполнить точные `terminal_path`, `expected_server`
   и целочисленный `expected_login` своего счёта в `service.json`. Сохранить файл и закрыть редактор.
   Для первой проверки оставить `enable_trading=false` и оба legacy-флага `false`.
5. Нажать **Telegram**, ввести token (скрытый ввод), chat ID и положительный user ID,
   затем сохранить. Прежние значения окно не показывает. Файл локальный и незашифрованный;
   права доступа Windows пользователь ограничивает самостоятельно. Не пересылать файл/скриншоты.
6. Нажать **READ_ONLY**, дождаться соответствующего сообщения в Telegram, проверить
   `/status` и `/settings`. `/start` в этом режиме запрещён. Сохранённые переменные окружения
   `TRADFI_TELEGRAM_*` по-прежнему имеют приоритет над файлом; загрузчик их не очищает при запуске сервиса.

Все данные находятся отдельно от кода:

```text
%LOCALAPPDATA%\AI_IMPULS_TRADFI_Manager\
  current.json                   текущий и предыдущий SHA
  releases\<SHA>\code\           код конкретного коммита
  releases\<SHA>\venv\           его собственное Python-окружение
  data\service.json              постоянная конфигурация
  data\telegram.json             локальные Telegram-настройки
  data\state.sqlite3             постоянная база
  data\tradfi.log                диагностический лог
  data\state-binding.json        защита от потери/подмены пути базы
```

Это отдельная новая установка. Старые папки проекта, их базы и конфигурация не
импортируются и не удаляются. Не запускать одновременно старый и новый сервис.
Пустая новая база не подтверждает сверку прежних EA/обязательств. Для новой установки
должно быть установлено, что активных циклов и обязательств нет; существующую историю
нельзя заменять новой базой ради обхода проверки. Не удалять `state-binding.json`.

## Обновление и rollback

Сначала завершить цикл штатно и остановить процесс. Кнопка **Остановить процесс…**
передаёт запрос штатного выхода; это НЕ `/stop`, не закрытие позиций и не отмена ордеров.
Во время активной торговли остановка процесса прекращает сопровождение. Для завершения
цикла сначала использовать `/stop` в Telegram и дождаться результата.

Кнопка **Установить / обновить** каждый раз проверяет актуальный SHA ветки `work`.
Код старой версии сохраняется. Текущая версия переключается атомарно лишь после успешных
загрузки, распаковки и установки зависимостей. При сбое прежний указатель остаётся.
После жёсткого выключения может остаться неполная папка версии; автоматически она не
перезаписывается — окно сообщит об ошибке, прежняя версия и данные сохраняются.

**Rollback кода** переключает текущий и предыдущий подготовленные SHA, не откатывает
SQLite, настройки, Telegram-файл или логи. Для обновления/rollback требуется неактивное
распознаваемое состояние без неразрешённых команд; несовместимая или потерянная база
блокирует операцию. Это не полное подтверждение брокерских обязательств и не миграция.
Контракт `managed_release.json` должен совпадать; изменение схемы или списка зависимостей
требует обновлённого загрузчика и отдельной проверки. Версии до появления managed-контракта
не поддерживаются этой процедурой rollback.

Работающий управляемый сервис удерживает системную блокировку до выхода, даже если
его `tradfi_main.py` запущен напрямую. Остаточный lock-файл после сбоя безопасен:
блокировку освобождает ОС, удалять файл по PID не требуется. Установщик также проверяет
штатную блокировку account/server/symbol для известного счёта из `service.json`.
Чужие старые процессы с другой конфигурацией или без совместимой блокировки полностью
обнаружить нельзя: перед первой установкой проверить старые окна/процессы вручную.

## Реальный запуск

Отдельная кнопка показывает предупреждение: сохранённый цикл и отложенный Telegram
`/start` могут исполниться сразу. Подтверждение запуска НЕ меняет JSON-флаги, настройки
MT5 или ACL. Все обычные execution guards остаются обязательными. READ_ONLY по умолчанию.
При ошибке процесс автоматически не перезапускается; окно остаётся открытым.
Закрыть окно штатно можно после остановки дочернего процесса.

## Источники и границы проверки

Загрузка — HTTPS GitHub API (`work` → SHA) и pinned GitHub archive. Архив ограничен по
размеру, числу файлов и степени сжатия; traversal, ссылки, специальные файлы, повторные
имена и опасные Windows-пути отклоняются до распаковки. Это доверие к указанному
репозиторию и TLS, не независимая подпись автора коммита.

Зависимости устанавливаются отдельным venv через официальный PyPI, только готовые
binary wheels; GitHub install-скрипты не исполняются. Нестандартные pip-источники из
окружения и конфигов отключены. Поддержанный список берётся из проверенного requirements;
при его изменении старый загрузчик откажет. `requests` и его транзитивные зависимости
не зафиксированы до каждого хеша, поэтому установка не заявлена как воспроизводимая
побайтно. Пакеты и импорт MT5 исполняются в Python только для проверки установки, без
initialize/login/order_send.

Offline-тесты подменяют сеть, pip и MT5; они не подтверждают Windows double-click,
реальный Tcl/Tk, msvcrt locking, установку wheels или работу с конкретным терминалом.
Нужен отдельный ручной Windows READ_ONLY прогон. Реальных секретов в тестах нет.
