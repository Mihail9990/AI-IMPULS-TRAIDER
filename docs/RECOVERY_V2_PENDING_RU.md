# Подготовка обновления RECOVERY (не активировано)

Подтверждён расчёт после первого SL:

- BUY: BUY STOP на прежнем входе, SELL STOP на SL минус отступ.
- SELL: SELL STOP на прежнем входе, BUY STOP на SL плюс отступ.

После последующего SL корзины:

- Закрылась SELL: BUY STOP = SL + отступ; SELL STOP = прежний вход − отступ.
- Закрылась BUY: SELL STOP = SL − отступ; BUY STOP = прежний вход + отступ.

Функция `recovery_range_after_sl` пересчитывает эти уровни для каждого переданного
последующего SL, в отличие от прежнего однократного расширения. Отступ передаётся
явно; нет округления, переноса пересечённого уровня или входа MARKET.

Пример: BUY4000 / SL3997 → BUY4000, SELL3996. Затем SELL3996 / SL3997.5 →
BUY3998.5, SELL3995. Зеркальная сторона проверяется тестами.

**Функция пока не подключена к отправке ордеров.** Действующий контроллер остаётся
на прежнем контракте `ticket_basket_v1`. Старые активные циклы и сохранённый долг
не переинтерпретируются. Публикации и торговли не было.

## Режим TP, выбираемый перед запуском

Подтверждено дополнительным уточнением «Тоесть после sl»:

- Перед стартом пользователь выбирает обычный либо ступенчатый TP для RECOVERY.
- Начальная позиция сохраняет обычный INITIAL_TP_DISTANCE; выбор её не меняет.
- Выбранный режим автоматически применяется после подтверждённого SL при входе
  в RECOVERY. Начальные ожидающие ордера не получают recovery-лестницу.
- Возможность переключить режим вручную внутри активного recovery-цикла сохраняется.
- При реализации предпочтение для будущего цикла и фактический режим активной
  корзины должны храниться отдельно. Перезапуск не должен незаметно переключать
  уже открытые билеты или пересчитывать лестницу после каждого частичного TP.

Это пока спецификация интерфейса и перехода, не действующая настройка опубликованного
контроллера. Расчёт гибридного TP, ручных ступеней и безопасное применение изменения
к фактическим открытым билетам ещё требуют уточнений и интеграционных проверок.

Перед подключением нужно определить:

1. Вход теперь подтверждён: средняя фактическая цена, взвешенная по объёму.
   Якорь SL — фактическая цена закрытия, а не выставленный защитный уровень.
   `confirmed_stop_anchors` проверяет CLOSED_EVIDENCE, принадлежность сделок,
   уникальность ID и полное совпадение входного/закрытого объёма каждого билета.
   При разных ценах SL-закрытий или смеси прежних TP и SL расчёт пока отказывает:
   нужно подтвердить объединение цен закрытия и состав билетов для средней входа.
   Денежный долг продолжает рассчитываться по фактическим сделкам и расходам.
2. Обычный / гибридный TP, ручные ступени и переключение на автоматические ступени.
3. Активацию, дистанцию и шаг trailing; правила обратной SL-лестницы.
4. Перенос диапазона относительно цены ручного закрытия и его разовое/постоянное действие.

Для интеграции обязательны подтверждённое закрытие предыдущей корзины, сверка всех
отмен и исполнений OCO и отсутствие UNKNOWN. План цен сам по себе не разрешает
отправку ордеров. Если обе стороны исполнились, требуется безопасная остановка и
сверка. Изменение контракта активного цикла потребует отдельной миграционной защиты.

## Отмена обратной SL-лестницы

Подтверждено пользователем: отмена обратной лестницы переносит общий SL оставшихся
частей на точку входа. Это отдельная команда, а не снятие защитных ордеров.

Требования к интеграции:

- Зафиксировать цикл, ревизию, состав фактически открытых билетов, прежние SL/TP
  и выбранный якорь входа. Способ определения общего входа после частичного TP
  пока ожидает ответа; не выбирать его скрыто.
- До отправки проверить допустимость нового SL для каждого остатка по свежим
  Bid/Ask, tick/stops/freeze. Недопустимый перенос отклоняется; нельзя снимать SL,
  округлять уровень произвольно или заменять перенос закрытием MARKET.
- Сначала сохранить намерение и остановить автоматическое движение обратной
  лестницы. TP не менять. Не создавать новые диапазонные ордера из этой команды.
- Отправлять изменения только собственным оставшимся билетам с долговечными ID.
  Повтор запроса/перезапуск не создаёт новое намерение; UNKNOWN сначала сверяется.
- Успех ответа MODIFY сам по себе не завершает отмену: требуется подтверждённое
  фактическое значение SL каждого ещё открытого остатка. Закрывшийся во время
  переноса билет учитывать только после подтверждения сделки и обновления долга.
- Частичный успех показывать как незавершённый перенос с фактическими SL. Не
  возвращать автоматически старые SL и не объявлять лестницу успешно отменённой.
- До полной сверки не возобновлять trailing/лестницу и не выполнять следующий
  переход диапазона. При доказанном отсутствии остатков завершать сверку по
  фактическим закрытиям, не посылать MODIFY несуществующим позициям.

Обратная лестница и её отмена пока не реализованы в рабочем контроллере. Этот раздел
фиксирует поведение и обязательные тесты: частичный отказ, UNKNOWN, закрытие между
MODIFY, изменение состава корзины, повтор запроса, перезапуск и READ_ONLY.
