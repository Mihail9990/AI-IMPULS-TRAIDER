# RECOVERY v2: подтверждённые диапазоны и незавершённая интеграция

## Подтверждённые правила

Первый SL:
- BUY: BUY STOP на фактическом прежнем входе, SELL STOP на последнем фактическом закрытии − отступ.
- SELL: SELL STOP на фактическом прежнем входе, BUY STOP на последнем фактическом закрытии + отступ.

После SL RECOVERY-корзины оба уровня считаются от последней фактической сделки
закрытия: BUY = последняя цена + отступ; SELL = последняя цена − отступ. Средняя
цена входа корзины больше не используется для этого перехода. Повторять после
каждого следующего SL, не сохранять прежнее однократное расширение.

Примеры: BUY4000 / закрытие SL3997 → BUY4000, SELL3996.
SELL-корзина / последнее закрытие SL3997.60 → BUY3998.60, SELL3996.60.
Для первоначального входа по нескольким исполнениям сохраняется фактическая
средняя, взвешенная по объёму, уже вычисляемая контроллером.

## Что реализовано

`LatestCloseBasketController` использует действующие ledger, gateway, проверки
принадлежности и OCO базового контроллера. До первого подтверждённого SL встречные
recovery-ордера не выставляются. Новые уровни сохраняются перед созданием намерений.
Каждая подтверждённая закрытая позиция сохраняет фактические ID, цену, объём,
время и причину закрытия в той же транзакции, что и денежный учёт.

Последняя цена выбирается по времени сделки; native MT5 сохраняет точность
миллисекунд. Порядок ответа API и числовой/лексический ID не подменяют время.
Одинаковое последнее время при разных ценах/причинах приводит к ручной сверке.
Неполные закрытия, UNKNOWN отмены и двойное исполнение OCO не разрешают новый вход.
Частичные TP отдельных билетов перед последним SL остальных покрыты тестами.
При последнем TP и оставшемся долге переход намеренно блокируется: это отдельное
неподтверждённое правило. Старый активный цикл не переинтерпретируется.

**Новый контроллер пока не подключён в runtime или симуляторе.** В них остаётся
`BasketController` прежней стратегии. Общая интеграция ожидает правил TP и ручных
управляющих действий ниже; нельзя выдавать этот промежуточный код за полный апгрейд.
Новый контроллер снова использует ступенчатый TP автоматически. Подготовленный
общий обычный TP для RECOVERY удалён по последнему указанию пользователя.

Тесты: BUY/SELL, actual gap/частичные TP, повторные SL, OCO/UNKNOWN, неполное
закрытие, неоднозначное время, native evidence, перезапуск, READ_ONLY и миграция.
Устаревший кандидат `confirmed_stop_anchors` со средней ценой SL и его тесты удалены.

## TP: последнее подтверждённое правило

- Только начальная позиция имеет обычный TP: INITIAL_TP_DISTANCE, по умолчанию 0.25.
- После SL в RECOVERY применяется только ступенчатый TP, автоматически по коду.
- Выбора обычный/ступенчатый перед запуском и кнопки включения ступенчатого TP нет.
- Общий обычный TP для RECOVERY, его расчёт и относящиеся только к нему тесты удалены.
- Уточнение автоматического и ручного расчёта ступеней ещё ожидается. Существующая
  лестница используется в подготовленном контроллере для offline проверок; не
  считать этим утверждёнными все правила будущего ручного управления.
- Сохранён фактический ledger долга/расходов. Остаток долга после TP не списывается.

## Оставшиеся критические правила

- Автоматический и ручной расчёт ступеней TP и изменение ступеней открытых билетов.
- Формула незаданных TP-ступеней среди вручную заданных и правила обратной SL-лестницы. Trailing отменён пользователем.
- Перенос диапазона относительно фактической цены ручного закрытия и его разовое/постоянное действие.
- Если последняя часть закрылась по TP, но после расходов остался долг: следующий переход пока не согласован.

## Отмена обратной SL-лестницы

Подтверждено пользователем: отмена обратной лестницы переносит общий SL оставшихся
частей на точку входа. Это отдельная команда, а не снятие защитных ордеров.

Требования к интеграции:

- Зафиксировать цикл, ревизию, состав фактически открытых билетов, прежние SL/TP
  и выбранный якорь входа. Способ определения общего входа после частичного TP
  пока ожидает ответа; не выбирать его скрыто.
- До отправки проверить допустимость нового SL для каждого остатка по свежим
  Bid/Ask, tick/stops/freeze. Недопустимый перенос отклоняется; нельзя снимать SL,
  округлять уровень произвольно или заменять перенос закрытием MARKET.
- Сначала сохранить намерение и остановить автоматическое движение обратной
  лестницы. TP не менять. Не создавать новые диапазонные ордера из этой команды.
- Отправлять изменения только собственным оставшимся билетам с долговечными ID.
  Повтор запроса/перезапуск не создаёт новое намерение; UNKNOWN сначала сверяется.
- Успех ответа MODIFY сам по себе не завершает отмену: требуется подтверждённое
  фактическое значение SL каждого ещё открытого остатка. Закрывшийся во время
  переноса билет учитывать только после подтверждения сделки и обновления долга.
- Частичный успех показывать как незавершённый перенос с фактическими SL. Не
  возвращать автоматически старые SL и не объявлять лестницу успешно отменённой.
- До полной сверки не возобновлять trailing/лестницу и не выполнять следующий
  переход диапазона. При доказанном отсутствии остатков завершать сверку по
  фактическим закрытиям, не посылать MODIFY несуществующим позициям.

Обратная лестница и её отмена пока не реализованы в рабочем контроллере. Этот раздел
фиксирует поведение и обязательные тесты: частичный отказ, UNKNOWN, закрытие между
MODIFY, изменение состава корзины, повтор запроса, перезапуск и READ_ONLY.

## Последнее изменение: TP1 и разовый перенос SL

Trailing и отдельная кнопка сдвига лестницы отменены. Ручное перемещение TP и SL
на графике сохраняется. Первая TP-ступень обязательна в настройках; явно заданные
остальные ступени сохраняются, незаданные рассчитываются автоматически. Расстояния задаются от входа. При заданной только TP1 остальные строятся с равным
шагом, покрывающим RECOVERY. Ручные расстояния сохраняются, пересчитываются только
пустые ступени. Общая точка отсчёта при разных входах частей ещё уточняется.

После подтверждённой первой TP-ступени SL оставшихся билетов один раз переносится
на фактический вход части №2 (общий SL для всех остатков). После завершения переноса ручной сдвиг SL остаётся на выбранном
уровне; повторный тик/перезапуск не возвращает его на вход.

В новом подготовленном контроллере реализована транзакция `stage_entry_sl_once`:
проверяет подтверждённое TP-закрытие в этой корзине, сохраняет все цели до отправки,
повторно проверяет quote/stops/freeze и прежнюю защиту, создаёт долговечные MODIFY
и ждёт фактического SL/TP каждого остатка. Частичный отказ сохраняет брокерскую
защиту и требует сверки, UNKNOWN не повторяет MODIFY. Закрывшиеся во время переноса
билеты учитываются по доказанному закрытию. Пока перенос не сверён, новая правка
защиты блокируется, чтобы она не гонялась с незавершённым автоматическим запросом.

В подготовленном новом контроллере транзакция теперь запускается автоматически
после подтверждённого TP именно части №1. Её вход не является якорем SL: берётся
сохранённый фактический вход части №2. Если часть №2 уже закрылась, её подтверждённый
вход сохраняет значение. При отсутствующем/неоднозначном входе №2 переход блокируется.
Закрытие другой ступени раньше №1 перенос не запускает. В старом runtime это
поведение пока не активировано: новый контроллер по-прежнему не подключён.

Проверки транзакции: подтверждённый TP, READ_ONLY, неверная котировка, повтор,
перезапуск, ручная правка после DONE и гонка до отправки, UNKNOWN, закрытие остатка,
ACK без readback, частичный отказ. Все проверки используют offline broker.

## Подготовленный планировщик заданных/автоматических TP

`configured_ladder` требует явный anchor, фактические входы и объёмы, текущий долг
и список расстояний по числу билетов. TP1 обязательна, пустая ступень обозначена
None. Якорь не выбирается внутри функции; привязка при разных фактических входах
частей ещё требует ответа до подключения этого планировщика к контроллеру.

Реализован проверяемый вариант общей сетки: для пустого слота i (нумерация с нуля)
расстояние TP1 + i × общий шаг; заданные слоты сохраняют собственные расстояния.
Выбирается минимальный целый по tick шаг, удовлетворяющий порядку ступеней и
покрытию долга через broker.profit. Ограничения заданных соседних ступеней сужают
допустимый шаг. При отсутствии решения, неточной цене, переставленных ступенях
или недостаточном покрытии полностью заданной сеткой план отклоняется.
Ручные уровни не сдвигаются, не добавляется скрытая дополнительная прибыль.

Для смешанной сетки это явная математическая модель; никакой отправки ордеров по
ней пока нет. Нужно подтвердить точку отсчёта входа и соответствие именно этой
общей сетки ожидаемому расположению пустых слотов. Если пользователь подразумевает
равные интервалы отдельно внутри каждого промежутка между ручными уровнями,
формулу необходимо заменить до интеграции, а не выбирать вариант молча.
