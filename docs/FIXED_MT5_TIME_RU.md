# Фиксированное время MT5

В конфигурации LIVE поле `market_time_offset_seconds` задаёт одно фиксированное смещение. Формула: UTC = исходное время MT5 − смещение. Значение по умолчанию 0 сохраняет официальный UTC-контракт SDK. Допустимы целые секунды, кратные 60, от −50400 до 50400; bool, строки и дроби недопустимы.

Для подтверждённого серверного формата UTC+2 устанавливается 7200 в конфигурации LIVE. Это не часовой пояс VPS и не настройка отображения. Сезонных поправок и автоматического угадывания нет. Уже существующие конфигурации автоматически не переписываются.

## Проверка перед настройкой

Не назначайте 7200 только по виду часов терминала. На Windows с открытым нужным MT5 выполните read-only диагностику `python tools/check_mt5_utc.py --config service.json`, затем повторите на свежих изменяющихся тиках. Она не открывает БД, не отправляет ордера, не меняет системные часы. Диагностика выводит профиль, независимый UTC и исходные/преобразованные отметки наблюдения. Проверка со смещением должна подтвердить и тик, и текущую/предыдущую M1. Это подтверждает текущие рыночные данные, а не все торговые условия и не исторические времена сделок.

## Защита

Тики и свечи преобразуются ровно один раз при входе. Согласованность `time`/`time_msc` проверяется по исходным значениям. После преобразования проверяются независимый UTC, свежесть, минутная сетка и длительность чтения. Если нет независимого UTC, данные устарели, смещения тиков и свечей отличаются или сервер сменил формат, действия блокируются. Коррекция не отменяет другие ограничения торговли и не включает торговлю.

Исходные timestamps сохраняются для диагностики. История сделок, их ID, локальные часы и монотонные дедлайны не сдвигаются. Внешние запросы получают существующие исходные данные согласно их контракту, а не автоматически исправленные исторические даты.

## Сохранённые базы

Профиль привязывается отдельно к каждой базе. Свежая база может принять явно заданное смещение. Старая база без привязки считается созданной с исходным профилем 0. Ненулевой профиль поверх старого состояния либо изменение уже привязанного профиля блокируется до отдельной сверки и плана миграции. Нельзя удалять базу или сменить её путь, чтобы обойти проверку: это потеряет управление долгом и открытыми обязательствами. Существующие позиции/ордера в MT5 проверяются отдельно; их наличие не становится безопасным только потому, что создан пустой файл.

## Ограничения проверки

Офлайн тесты не доказывают реальное смещение конкретного Windows MT5. Подтверждение 7200 и работа LIVE с реальным терминалом требуют отдельной read-only проверки. В этой реализации настройка сама по себе не означает VERIFIED.

## Короткое ожидание первого тика новой M1

На границе минуты котировка и M1 могут обновиться не одновременно. Если до границы
были проверенные согласованные данные, при задержке ровно на одну соседнюю минуту
бот ждёт их согласования не более **3 секунд от границы M1**. Повторные проверки
не продлевают этот срок. Во время ожидания новые заявки брокеру не отправляются;
существующие брокерские SL/TP остаются, исполненные билеты продолжают сверяться.

Команды панели принимаются с состоянием «Ожидание свежих данных». После первого
согласованного tick/M1 их актуальность, цикл, настройки, котировка и ограничения
проверяются заново. Только затем допускается исполнение. «Стоп» и отмена работают
раньше отложенных входов. Выбранная текущая/следующая свеча не переносится на другую.
Принятие команды не является подтверждением сделки.

Если данных нет к сроку, сохраняется обычная блокировка времени. Потеря UTC,
повреждённые данные, скачок часов, старые данные вне перехода M1 и другие ошибки
блокируют сразу. Старая блокировка не снимается автоматически. После перезапуска
отложенные команды отменяются; неопределённый исход UNKNOWN никогда не повторяется.
Проверка цены по-прежнему точная: устаревшая цена не заменяется незаметно новой.
