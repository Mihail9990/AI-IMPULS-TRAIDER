# HTTPS для телефона — Windows VPS

Мастер находится в **полном архиве проекта**, `START_INSTALLER.bat` → **HTTPS для телефона…**.
Рядом с `install_tradfi.py` нужен `https_setup.py`. Старого одиночного установщика недостаточно.
Нужны Windows x64, Python 3.13 с Tk, права администратора для служб, интернет для загрузки Caddy/ACME.
Открытие окна ничего не устанавливает. Подготовка плана читает конфигурацию и состояние Windows.

## Порядок

1. В существующем установщике нажмите **Остановить процесс…** и дождитесь завершения READ_ONLY. Это не закрывает позиции. При активной реальной торговле сначала безопасно завершите цикл; этот мастер предназначен для настройки с `enable_trading=false`.
2. Из полного нового архива откройте `START_INSTALLER.bat` от имени администратора под **тем же пользователем Windows**, который установил бота. Не меняйте пользователя: путь данных зависит от LOCALAPPDATA.
3. **HTTPS для телефона…** → введите публичный IP VPS без схемы/порта → **Подготовить план**. Пароль вводится только локально в `service.json`, минимум 32 символа. Переменная TRADFI_WEB_PASSWORD, если присутствует, имеет приоритет; пустая переменная не разрешает fallback.
4. Проверьте имя и путь прежней службы, адрес, резервную копию. **Применить** отдельно подтверждает остановку/отключение автозапуска старой службы и установку новой. Старая служба при переносе не удаляется.
5. Закройте мастер → **READ_ONLY** в установщике. Затем откройте HTTPS адрес на телефоне. Например, IP `130.94.67.32` даёт origin `https://130.94.67.32` без конечного `/` или `:443` в настройках. В адресной строке браузер может отображать `/` — это нормально.
6. **Диагностика HTTPS** проверяет доверие сертификату Windows и ответ страницы без пароля. Проверка с VPS не доказывает доступ из мобильной сети: отдельно откройте адрес на телефоне. Предупреждения TLS не обходить.

После задания public_origin вход в обычную HTTP-панель не используется: cookie становится Secure, Origin должен быть публичным HTTPS origin. Панель по-прежнему слушает только `127.0.0.1:8765`; Caddy передаёт этот Host, сохраняя Origin и cookies. Старый basic_auth анализатора не переносится. Авторизация бота остаётся обязательной.

## Что устанавливается

Новая служба `AIImpulsHTTPS`, Caddy **2.11.7** из официального Windows amd64 release, проверка SHA256 архива до выполнения. Стабильная папка `%LOCALAPPDATA%\AI_IMPULS_TRADFI_Manager\https`, независимая от релизов кода и анализатора. Хранилище сертификатов `https\certificates`. Права этой папки ограничиваются текущим пользователем, SYSTEM и администраторами. Ключи и резервные копии остаются локальными; не отправляйте эту папку, service.json или service.reg в чат/GitHub.

Caddy запускается Windows SCM автоматически и самостоятельно продлевает публичный IP сертификат Let's Encrypt с профилем `shortlived` (160 часов). Сертификат не включён в архив. Требуются доступные извне 80/443 и исходящий HTTPS для ACME; мастер **не меняет firewall, облачные security groups, маршрутизатор или DNS**. Если выдача не завершилась, установка службы не означает готовность HTTPS. После перезагрузки Caddy запускается автоматически, но бот **не запускается автоматически**: нажмите READ_ONLY в установщике под нужной MT5 сессией. При закрытом backend возможен HTTP502.

Административный API Caddy слушает только `127.0.0.1:2020`. Он не публикуется через proxy. Старые правила basic_auth/Host могут быть причиной прежнего HTTP403; новая конфигурация их не наследует. Caddy stderr не экспортируется в логи бота; для непонятных ошибок выдачи сертификата нужна дополнительная диагностика Windows/Caddy.

## Ранний отчёт и повтор после отказа

До загрузки Caddy мастер создаёт `%LOCALAPPDATA%\AI_IMPULS_TRADFI_Manager\https-attempt.json`.
Этот файл находится **вне папки https**, поэтому появляется и при отказе загрузки/проверки прав.
Он содержит этап, безопасный код ошибки, контрольные суммы и признак начала изменений;
пароль, полный config, сырые ответы SDK/Windows и текст сетевого исключения не записываются.
Если сам отчёт записать нельзя, окно прямо сообщает об этом и не обещает наличие журнала.

Кнопка **Диагностика** показывает наличие раннего отчёта, папки HTTPS, резервной копии,
transaction.json, этапы, код HTTP/команды (если получен), состояние службы и проверку HTTPS.
На новом VPS без папки https это допустимый исходный результат, а не повод удалять lock-файлы.

Apply и диагностика выполняются в фоне. Повторные кнопки заблокированы на время операции;
закрытие мастера/установщика до её завершения запрещено. Отмена подтверждения ничего не меняет.
Длительный системный вызов имеет тайм-аут; после неизвестного исхода автоматического повтора нет.

Для ошибки **до изменения конфигурации или служб** предусмотрена кнопка
**Восстановить подготовку**. После отдельного подтверждения она сверяет исходный config,
службы/порты, принадлежность каталога и все существующие файлы с манифестом.
Подтверждённые файлы перемещаются целиком в `https-recovery/<id>` с сохранением копий и ACL;
ничего не удаляется. После этого нужен НОВЫЙ план и новое подтверждение Apply.
При частично записанном/изменённом файле, неизвестном каталоге, ссылке или изменении службы
восстановление отказывает. После этапов config/service_create/service_start такой повтор
запрещён: сначала диагностика и отдельный откат/разбор, без дублирования службы.

Старые неразмеченные частичные папки автоматически не присваиваются и не очищаются.
Сохраняйте их для диагностики. Ранний отчёт не устанавливает задним числом причину
предыдущего отказа, произошедшего до этой версии программы.

## Конфликты и восстановление

При неизвестном владельце 80/443/2020, смене процесса, чужом имени новой службы, изменённой конфигурации, недостаточном пароле или работающем backend применение блокируется. PID из старого снимка никогда не используется как разрешение остановки. Произвольный `taskkill` отсутствует.

Автоматически распознаётся **только прямой запуск** `caddy.exe run --config ... [--adapter caddyfile]` с абсолютными путями exe/config в `XAUUSDs_Strategy_Analyzer\https_ip`, службой LocalSystem без зависимостей; работающий PID, путь и команда должны соответствовать службе. NSSM/WinSW, другая папка, относительные пути, дополнительные параметры или несколько подходящих служб требуют отдельной проверки. Не переименовывайте чужую папку ради прохождения проверки. Если текущая старая служба использует обёртку, эта версия намеренно её не изменит.

Перед переходом сохраняются Caddyfile, экспорт реестра службы, ACL службы и service.json. Журнал `https\transaction.json` хранит этапы без пароля. При частичном отказе повторное применение заблокировано до явной сверки и восстановления подготовки, если оно допустимо. **Откат HTTPS** при остановленном боте возвращает service.json только если его никто не редактировал, останавливает и отключает новую службу, восстанавливает прежний режим запуска/состояние старой службы. Не затрагивает SQLite, настройки стратегии, файлы сертификатов, MT5 или симулятор. При изменённых файлах/службе откат отказывает вместо перезаписи. После отката новая служба и файлы сохраняются отключёнными; повторная установка поверх них не автоматизирована и требует диагностики. Это ограничение защищает от повторного выполнения незавершённого перехода.

## Отдельное удаление старой службы

Архив `Old-Analyzer-HTTPS-Removal-*.zip` содержит `REMOVE_OLD_ANALYZER_HTTPS.bat` и helper. Требует установленного Python 3.13 с Tk; это не самостоятельный EXE.

Извлеките архив, запустите BAT от администратора → **Диагностика** → проверьте путь/имя → **Удалить старую службу** → подтвердите. Он останавливает и снимает с регистрации только проверенную службу анализатора. Не удаляет папки, ключи, сертификаты, MT5, firewall или новую службу бота. Копия хранится в `%LOCALAPPDATA%\AIImpuls_OldHTTPS_Backups\backup-...`; **Восстановить** предлагает выбрать эту папку. Для восстановления нужны неизменённые оригинальные файлы анализатора и свободные порты. Не удаляйте старую папку, пока нужна возможность восстановления.

При занятии порта другим процессом после удаления сообщается фактический результат, а не обещание свободного порта. При неизвестной обёртке или чужом Caddy удаления не будет. Частично остановленную, но ещё существующую исходную службу можно восстановить из копии, если её идентичность и файлы не изменены.

## Проверки и границы

Unit-тесты используют имитацию Windows/SCM; браузерные проверки основного бота используют offline broker. Сам Caddy проверялся только командой `adapt` (разбор конфигурации, без provisioning/start). Реальная Windows служба, UAC, ACL, IPv6/мобильный маршрут, ACME issuance/renewal и восстановление реестра на VPS здесь не выполнялись. До телефона остаётся локальная проверка пользователя. Установка этого кода не исправляет отсутствие котировок MT5 и не разрешает реальные сделки.
