# Read-only проверка старой истории MT5

`tools/mt5_history_probe.py` — самостоятельный файл без зависимостей от стратегии.
Требуется установленный официальный MetaTrader5, открытый терминал
`C:/Program Files/MetaTrader 5/terminal64.exe`, текущий счёт Bybit-Live-6 UST hedging.
Algo Trading оставить OFF. Скрипт привязывается к текущей сессии, проверяет неизменность
счёта перед/после чтений, но не выводит его номер и не авторизуется заново.

Предварительный шаг: MT5 → История → правой кнопкой → Вся история. Проверить наличие
старых XAUUSD.s и дату последнего события. Это проверка видимости в GUI, а не доказательство
того, что выбор периода GUI управляет Python API. Скриншот с реквизитами не требуется.

Из папки со скриптом в Windows cmd (не в Python `>>>`):

```bat
py mt5_history_probe.py
```

Отчёт `mt5_history_report_<UTC-время>.txt` сохраняется рядом; старые файлы не затираются.
Консоль показывает прогресс до каждого запроса; загрузка истории может занять время.
Ctrl+C прекращает диагностику. Скрипт отключает Python API, терминал не закрывает.

Окно ограничено 90 днями с запасом 3 часа на шкалу timestamps. Запрашиваются orders и deals
без group-фильтра, затем локально выделяется точный XAUUSD.s. Наружу выходят только
общие количества и количество точных совпадений символа. До трёх существующих событий
каждого типа сравниваются с ticket/position-запросами; идентификаторы используются внутри.
Для deals параметр ticket означает ticket ордера, не ticket самой сделки.

Для выбранного события строятся узкие окна ±2 секунды (с округлением границ максимум
5 секунд) вокруг raw timestamp и вокруг UTC-кандидата по календарю Bybit. Это гипотезы:
временная шкала истории ещё не подтверждена. Сравнивается присутствие именно выбранного
события, а не только общее количество. Для orders отдельно проверяются setup и done.
Каждое окно передаётся и числом epoch, и timezone-aware UTC datetime. Повторный широкий
запрос проверяет стабильность набора ticket без вывода идентификаторов.

Результат не утверждает ни полноту истории, ни одобрение профиля. Совпадение события
только в RAW_ENCODING свидетельствует о фильтрации в raw-шкале для этого события;
само по себе это не доказывает истинное UTC-время исполнения. Для подтверждения последнего
нужна независимая временная опора или спецификация брокера. Возврат в обоих/ни одном окне,
None и изменение результатов требуют разбора. DST gap/fold не разрешаются угадыванием.
Пустота означает EMPTY_SYMBOL_INCONCLUSIVE; события могут быть старше 90 дней, недоступны
в истории терминала или иметь другой символ. Новых сделок для этой проверки не создавать.

Торговых методов нет. Конфиги/SQLite/профиль адаптера не читаются и не изменяются.
В отчёт не попадают номера счетов, tickets, PnL, баланс, комментарии и исходные ошибки.
Торговая блокировка HISTORY_TIME_PROFILE_UNVERIFIED остаётся без изменений.

Offline тесты: `python -m unittest discover -s tests -p test_mt5_history_probe.py -v`.
