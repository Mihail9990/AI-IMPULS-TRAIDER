# Простой HTTPS на новом VPS

Этот вариант предназначен **только для чистой установки HTTPS**. Старые VPS и
частичные установки он не очищает, не восстанавливает и не переносит. Утилиты сброса нет.

1. Установите Python 3.13 x64 и бот через `START_INSTALLER.bat`. Сохраните настройки
   в Блокноте: `enable_trading=false`, `web.enabled=true`, `web.host="127.0.0.1"`,
   `web.port=8765`, собственный `web.password` не менее 32 символов. Не присылайте файл
   настроек. Если задана `TRADFI_WEB_PASSWORD`, она имеет приоритет.
2. Скачайте браузером [официальный Caddy 2.11.7 Windows amd64 ZIP](https://github.com/caddyserver/caddy/releases/download/v2.11.7/caddy_2.11.7_windows_amd64.zip).
   Не распаковывайте его и не обходите предупреждения TLS.
3. Остановите READ_ONLY, закройте прежний HTTPS мастер. В полном архиве проекта
   запустите **SETUP_PHONE_HTTPS.bat от имени администратора**, под тем же пользователем,
   который установил бот. Рядом должны оставаться `setup_phone_https.ps1`,
   `https_simple.py` и `https_setup.py`.
4. Введите **IP нового VPS**, выберите скачанный ZIP и подтвердите показанные изменения.
   Никаких команд PowerShell вводить не нужно. Старые IP не подставляются автоматически.
5. После успеха отдельно запустите READ_ONLY и откройте показанный HTTPS адрес на телефоне.
   Проверка сертификата обязательна. Успех установки службы не означает, что сертификат
   уже выдан или что сеть провайдера пропускает соединения.

Проверяется закреплённая SHA256 ZIP, структура архива и AMD64 исполняемый файл;
используются те же проверенные в памяти байты. Python не скачивает Caddy в этом режиме.
Служба `AIImpulsHTTPS` запускается автоматически при загрузке Windows, бот — нет.
Backend остаётся loopback, upstream Host — `127.0.0.1:8765`; пароль, cookies и Origin
не подменяются. Caddy сам продлевает сертификат Let's Encrypt shortlived.

После одного подтверждения установщик проверяет конфигурацию, службы, порты и
существующие правила firewall, сохраняет резервную конфигурацию, устанавливает Caddy
и службу, затем создаёт три именованных правила Windows:

- `AIImpulsHTTPS-HTTP`: входящий TCP 80 разрешён;
- `AIImpulsHTTPS-TLS`: входящий TCP 443 разрешён;
- `AIImpulsHTTPS-Backend`: входящий TCP 8765 заблокирован.

Другие правила не изменяются. Уже существующие правила с этими именами принимаются
только при совпадении проверяемых параметров и группы. Конфликт вызывает отказ.
Облачный firewall провайдера не меняется: при его наличии 80/443 требуется разрешить
отдельно. Внешний 8765 открывать нельзя. BAT задаёт execution policy только для своего
процесса PowerShell; системную политику Windows он не меняет.

После отказа **не повторяйте установку и не удаляйте папку вручную**. Частично созданная
служба/файлы сохраняются, а повторный запуск отказывает. Для текущей версии это намеренное
ограничение простого пути; сложного recovery workflow в нём нет. Безопасный отчёт
`https-simple-diagnostic.json` находится в `%LOCALAPPDATA%\AI_IMPULS_TRADFI_Manager`.
Ранний журнал `https-attempt.json` также сохраняется. При сбое firewall служба может уже
работать; отчёт явно указывает этап `firewall`. Ни одна ошибка не запускает торговлю.

Старый мастер остаётся для диагностики прежних установок. Для новой установки используйте
именно BAT из этого документа, а не последовательность recovery/plan/apply старого мастера.

Проверки разработки: offline Python tests, настоящий Linux Caddy adapt/validate,
PowerShell 7 parser и mocked firewall cmdlets. **Windows PowerShell 5.1, UAC, SCM,
настоящий Windows Firewall и выдача/продление публичного сертификата на VPS не проверены.**

Контракты: [Caddy Windows service](https://caddyserver.com/docs/running),
[Windows Firewall PowerShell](https://learn.microsoft.com/en-us/windows/security/operating-system-security/network-security/windows-firewall/configure-with-command-line).
