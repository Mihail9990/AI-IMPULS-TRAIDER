Рабочее дерево до начала чистое. Инструкций AGENTS.md/SKILL.md в репозитории,

## Этапы

1. Зафиксировать baseline полным offline runner. Создать отдельную ветку.
2. Ввести строгие типы настроек модулей и команд пользователя, единый owner-only
   обработчик действий Telegram/UI с durable idempotency и optimistic revision.
3. Интегрировать выбор auto/semi и пользовательские triggers. Range вычисляется
   от Ask для BUY и Bid для SELL в одном снимке при получении команды; эти же
   стороны используются брокером для срабатывания. Mid не применяется.
4. Ввести отдельный fixed-SL recovery-модуль и денежный ledger из подтверждённых
   фактов, с неизменными guards времени/ownership/reconcile. Не смешивать два
   TP-движка на одной позиции. Динамические настройки применяются транзакционно.
5. Изменение pending — только после подтверждённых отмен, с разрешением fill race.
   Изменение protection — через подтверждённую позицию. Для нового market close
   потребуется отдельный intent/evidence contract; никаких реальных отправок.
6. Локальный responsive web UI и backend с общим controller, mock XAUUSD.s,
   графиком, touch zoom/pan и drag preview -> Apply. Только loopback и fake broker;
   реальные secrets/доступ/публикация вне объёма. Telegram предлагает кнопку,
   не открывает браузер. Никакого голосового AI или прогнозов.
7. Полные offline тесты, restart/race/UNKNOWN/time-safety, UI проверки и независимый
   review новых модулей и конечного diff. Commit и отчёт по границам реализации.

## Неоднозначности, переданные родительскому потоку

- Когда переключать TP-движок при активной позиции: следующий полный цикл или
  немедленный перенос текущего остатка?
- Пересечённые новые pending-уровни после отмены: отклонять или использовать
  существующую логику MARKET?
- Точность полного денежного погашения нового recovery: <=0 UST или 0,01 UST?
  Предложено сохранять INITIAL_SIZE и рассчитывать TP по денежной доле, учитывать
  неизвестные будущие издержки при фактическом закрытии. Счётчик N не доказывает
  погашение и не обнуляет остаток.

Зависимые изменения стратегии ожидают ответа; независимые инфраструктурные части
могут быть реализованы до ответа. Семантика позднего SL из baseline не меняется молча.

## Зафиксированный baseline и первый этап

Baseline offline: 405 tests, OK, Blocked real network attempts: 0.
Добавлен owner-only ActionGateway с резервированием durable receipt до выполнения,
проверкой версии Apply и запретом replay после неопределённого исхода. OwnerMailbox
не передаёт SQLite/controller рабочим HTTP-потокам, публикует копию состояния и
результаты Apply. Это инфраструктура; новые торговые команды пока не подключены.
Для будущих price-sensitive Apply дополнительно необходима сверка old/new preview
со свежим broker snapshot; control_revision сам по себе не подтверждает цену.

Дополнительное уточнение: при 2 выполненных TP из N=3 и изменении N на 5 во время
позиции делить текущий долг на 3 оставшиеся части или заново на 5? Это влияет на
немедленное изменение TP, поэтому правило не выбирается молча.

Первый этап проверен полным runner: 419 tests, OK, Blocked real network attempts: 0.
Независимый review выполнен: учтены UNKNOWN для неопределённых ошибок generic
executor, явный ActionRejected для доказанного отказа и owner-check даже при

## Полученные решения пользователя

Все четыре правила подтверждены: движок переключается со следующего полного
цикла; пересечённые новые pending отклоняются без MARKET; новый recovery
заканчивается только при остатке <=0; N переразбивает текущий долг заново на N,
сохраняя реализованную прибыль, и немедленно пересчитывает TP открытой позиции.
Обычный TP по умолчанию теперь 0.25. Manual close отдельно подтверждается и
сверяется по фактическим сделкам, обновляет долг и останавливает новые входы.
График отдельной вкладкой: tap/drag только preview; create/move/delete/close
только после подтверждения. Mock поток отмечен явно, без MT5 и credentials.
