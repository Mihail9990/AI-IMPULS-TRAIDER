# Обновление LIVE и состояние SQLite

Новая установка включает `market_time_mode=mt5_raw_v1` и
`execution_contract=cycle_scoped_identity_v1`. Ручное вычитание 7200 не требуется.
Это выбор протокола, а не разрешение торговать: `enable_trading`,
`legacy_ea_removed` и `legacy_state_reconciled` по умолчанию `false`.
Нельзя отмечать сверку выполненной автоматически. Логин, пароль панели и
фактическое состояние счёта нужно проверить отдельно. Обновление не переписывает
существующий `service.json` и не меняет временной профиль старой SQLite.

## Обновление кода

После остановки процесса никакое сохранённое состояние бота не блокирует
обновление: цикл, фаза, RECOVERY, история, UNKNOWN-команды или версия снимка
не проверяются установщиком. SQLite сохраняется без изменения. Установщик
переключает только код, не мигрирует данные, не отправляет заявки и не запускает
бота после обновления.

Остаются проверки файлов и доступа: процесс должен быть остановлен, путь и
привязка SQLite должны сохраняться, файл должен читаться и пройти проверку
целостности. Это защита данных от потери/повреждения, а не проверка состояния
бота. Сохраняются резервная копия и проверки архива/релиза.

На следующем отдельном запуске LIVE сохранённый цикл может продолжиться.
Проверки совместимости и сверки самого бота не изменены. Обновление кода
не является подтверждением безопасного состояния счёта. Остановка процесса
не закрывает позиции и не отменяет ордера в MT5.

## Откат к предыдущей версии

Для rollback сохранена строгая проверка состояния: старый код может быть
несовместим с текущими обязательствами. Точные категории:

- `CYCLE_NOT_FINISHED`: сохранён цикл.
- `PHASE_REQUIRES_RECONCILIATION`: сохранённая фаза требует проверки.
- `COMMAND_NOT_TERMINAL`: команда без окончательного результата.
- `COMMAND_JOURNAL_MISMATCH`, `DEAL_LEDGER_MISMATCH`: расхождение журналов.
- `SNAPSHOT_MISSING_OR_INVALID`: нет надёжного снимка контроллера.
- `STATE_SCHEMA_INCOMPATIBLE`, `LEDGER_CONTRACT_INCOMPATIBLE`,
  `COMMAND_SCOPE_INCOMPATIBLE`: несовместимый формат/контракт.

`INTEGRITY_CHECK_FAILED` и `STATE_UNREADABLE` относятся к файлу SQLite,
а не активности бота, и блокируют также обновление. Секреты и номера счетов
в текст ошибки не включаются. SQLite не удалять.

При rollback допускается известная пустая база первого неудачного запуска
с корректными привязками. Любые операционные строки или неизвестная схема
не допускаются. Данные при этом не меняются.
