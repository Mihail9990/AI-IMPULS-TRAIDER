# Независимые LIVE и PAPER

У приложений один исходный репозиторий, но **разные установленные копии кода**.
Ни одна из установок не импортирует код, конфигурацию или данные второй.

## Запуск

- `START_LIVE.bat` открывает управление основным ботом.
- `START_PAPER.bat` открывает управление симулятором.
- `START_INSTALLER.bat` открывает выбор этих двух отдельных окон.

Каждое окно имеет собственные установку/обновление, настройки, запуск, остановку
и rollback. Закрытие одного окна не требует остановки второго приложения.
В LIVE реальное исполнение по-прежнему запускается отдельным действием;
обычный запуск — READ_ONLY. PAPER не допускает `--execute`.

Каталоги по умолчанию:

```
%LOCALAPPDATA%\AI_IMPULS_LIVE\
%LOCALAPPDATA%\AI_IMPULS_PAPER\
```

В каждом находятся собственные `releases\<sha>\code`, `venv`, `current.json`,
`data\service.json`, `data\state.sqlite3`, журналы, резервные копии и ярлык
`START_LIVE.bat` либо `START_PAPER.bat`. Это обычные отдельные файлы, не ссылки.
Путь данных ограничен собственной папкой `data`. Роль установки неизменна.

По умолчанию панели доступны локально по `http://127.0.0.1:8765` и
`http://127.0.0.1:8766`. Cookies, пароли, очереди и API раздельные. Ошибка в
настройках другого приложения не блокирует собственный запуск. Обновление
проверяет и обслуживает только свою установку; другое приложение может работать.
Откат меняет только собственный код, а не SQLite или настройки.

## Перенос прежней общей установки

Если уже существует `%LOCALAPPDATA%\AI_IMPULS_TRADFI_Manager`, сначала используйте
кнопку **«Перенести прежнюю общую установку…»**, а не создавайте пустые новые
установки. Закройте оба прежних процесса. Для переноса LIVE состояние должно
пройти прежние проверки: активный или неизвестный цикл не переносится автоматически.

Перенос выполняется для обоих приложений одной операцией:

1. Проверяются роли, пути, блокировки и целостность исходных баз. Назначения
   должны быть пустыми либо принадлежать тому же незавершённому переносу.
2. В каждом новом каталоге отдельно загружается совместимый релиз и создаётся
   отдельное Python-окружение. Новый код не запускается.
3. SQLite переносится через backup API, включая данные WAL. Настройки, история,
   идентификатор PAPER, RECOVERY, команды и состояние продолжения сохраняются.
   Меняются только собственные пути данных/логов; у PAPER исполнение остаётся
   выключенным. Профиль времени не меняется и сохранённые метки не пересчитываются.
4. Прежний каталог помечается архивным: старый runtime отвергает его, чтобы не
   воспроизвести устаревший журнал. Исходные базы, конфигурации и код остаются на месте.
5. После проверки завершения снимается блокировка новых установок. Никакие
   торговые процессы автоматически не запускаются.

При прерывании до архивирования новые приложения остаются заблокированными.
Повторите ту же операцию с теми же каталогами. После архивирования повтор только
завершает активацию, **не перезаписывает** уже активированные данные. Не удаляйте
файлы привязок/миграции и не пытайтесь запустить старую копию через другой путь.
Временные файлы либо неготовые релизы не считаются успешной установкой.
Если у базы назначения обнаружены оставшиеся `-wal`, `-shm` или `-journal`,
перенос останавливается для проверки. Эти файлы не удаляются автоматически:
замена одного основного SQLite-файла могла бы воспроизвести чужой старый WAL.
Новые копии создаются самодостаточными; рабочий режим WAL включается только
при последующем запуске приложения. Папки `data` со ссылкой/junction наружу
также отклоняются. Одновременный перенос или установка в одну папку блокируется.

## Внешние зависимости и границы проверки

- MT5 остаётся внешним источником. Перенос не устанавливает второй терминал,
  не меняет логин MT5, его разрешения или торговые параметры.
- Если `terminal_path` одинаковый, отключение самого терминала влияет на оба
  приложения. Два Python-клиента требуют отдельной проверки на Windows без сделок;
  автономность процессов не является гарантией независимости одного общего MT5.
- Для полной независимости источника можно отдельно настроить второй терминал,
  но это не выполняется данной миграцией автоматически.
- Существующая HTTPS-служба не переносится и не изменяется автоматически. Старый
  каталог нельзя удалять, если на него ссылается эта служба. Две публичные ссылки
  требуют отдельной конфигурации HTTPS; backend-порты остаются loopback.
- Разделение не отменяет проверки UTC, свежести и идентичности источника. График
  может отображать RAW/UNVERIFIED, но это не разрешает виртуальные или реальные
  исполнения на неподтверждённых данных.

Офлайн-тесты проверяют файлы, транзакции переноса, блокировки, независимость
обслуживания и маршрутизацию. Нативная Windows/MT5 и внешняя HTTPS-проверка являются
отдельными этапами, не заменяются тестами с фиктивным MT5.
