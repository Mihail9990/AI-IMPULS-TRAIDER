# SMC и ликвидность основного графика

В панели оставлен только аналитический слой **SMC / зоны** основного M1-графика.
Свечные паттерны, графические фигуры и линии направления тренда удалены.
TA-Lib, trendln и собственный модуль фигур больше не импортируются и не вычисляются;
их зависимости исключены из установки аналитики. Торговая стратегия и её M1,
команды входа, изменения SL/TP, ордера и история сделок не меняются.

## Состав и ограничения

`modules` содержит только `smc`, `overlays` только `structure`.
SMC рассчитывает FVG, подтверждённые локальные экстремумы, BOS/CHoCH,
зоны ликвидности и пересечения этих зон. Компоненты проверяются независимо:
сбой отдельного расчёта обозначается в `modules.smc.components` и не создаёт
подставных отметок. Отсутствующая библиотека не означает отсутствие найденных зон.

Зоны объединяют подтверждённые однотипные экстремумы в пределах 1% полного
high-low диапазона ограниченного снимка, а не 1% цены. Каждый экстремум
требует по пять закрытых свечей справа и слева. Для sweep должна уже
завершиться правая проверка последнего экстремума группы. Уровни, индексы,
состав группы и первое пересечение проверяются по исходным OHLC.
До 12 зон и 8 связанных пересечений сохраняются внутри общего лимита
80 структурных отметок. Алгоритм использует не более 300 последних закрытых баров.

Это **OHLC-оценка**, не реальные лимитные заявки, стопы, биржевые объёмы или
стакан. Отметки не являются торговыми сигналами. Историческая координата
не означает, что результат был известен тогда: `known_at` относится к снимку.
Старые группы могут пересматриваться при изменении диапазона снимка;
этот слой нельзя использовать как историю доступных в прошлом сигналов.
Объёмозависимые сигналы, order blocks и автоторговля по аналитике не включены.

## Источник, время и API

`GET /api/analysis?timeframe=M1` сохраняет авторизацию и возвращает кэш.
Общий read-only API по-прежнему поддерживает M1/M15/M30/H1 и необязательный
`bars=50|100|200|300|500`; без параметра запрашивается до 500 закрытых баров.
Это совместимость backend, а не отдельные пользовательские графики.
`requested_bars` обозначает запрошенную глубину, фактическая история может быть короче.
Кэши и retry-состояние разных глубин независимы. Ограничение адаптера SMC
в 300 баров действует и при запросе источника на 500 баров.

Читаются собственные нативные свечи MT5, без агрегации или заполнения пропусков.
Проверяются порядок, границы периодов, конечные положительные OHLC,
закрытость свечи, identity счёта/сервера и путь терминала. Проверки времени
сохраняют выбранный режим: фиксированное смещение или явный BROKER_RAW.
В BROKER_RAW последняя нативная bar0 определяет текущую незакрытую свечу;
давность по часам компьютера намеренно не оценивается.

Слой сопоставляет symbol, feed instance, временной домен и значения общих
закрытых свечей с основным источником. Несовпадение скрывает слой.
Проверка последней закрытой M1 защищает от отображения отстающего расчёта.
15-секундный опрос HTTP не является обещанием такого же срока перерасчёта.
Watchdog ограничивает отдельное задание 20 секундами; при нескольких глубинах
последовательный цикл может быть дольше. Время получения HTTP-ответа не равно
времени вычисления кэша. См. `generated_at` и диагностический возраст кэша.

## Изоляция

Торговый поток передаёт только небольшой снимок проверки времени и не ждёт
истории или расчётов. Нативные чтения и SMC выполняются в отдельном killable
процессе, а HTTP читает кэш. Worker не получает controller, SQLite,
журнал сделок или пароль веб-панели и не отправляет торговых заявок.
Ограничены IPC, время ответа, перезапуски и число кэшируемых глубин;
после отсутствия запросов worker останавливается. Проверки READ_ONLY,
UNKNOWN, подтверждения SL/TP и торговые блокировки не меняются.

## Отдельная среда аналитики

Используется стандартный CPython 3.13 x64, не free-threaded, и отдельная
`.venv-analysis-313`. LIVE Python и его зависимости установщик аналитики не меняет.
Запуск дочернего интерпретатора идёт без shell, с `-I`, без наследования
PYTHONPATH, user-site и переменных TRADFI. Вывод библиотек отделён от JSON IPC.

`requirements-analysis.txt` сохраняет закреплённые версии SMC 0.0.27,
numpy, pandas, numba/llvmlite и необходимых временных зависимостей;
MetaTrader5 устанавливается только на Windows. Старые установленные пакеты
TA-Lib/trendln автоматически не удаляются, но больше не требуются и не исполняются.

Запуск установки: `SETUP_ANALYSIS.cmd`. Установщик не переписывает торговую
конфигурацию. Настройка `analysis_python` должна указывать абсолютный путь
к отдельному Python 3.13 venv, не к интерпретатору LIVE.

Проверки без терминала, сетевого соединения и изменения конфигурации:

```text
python tools/run_offline_tests.py
python tools/check_analysis_dependencies.py
python tools/check_analysis_dependencies.py --smoke --require-lock
```

Последняя команда должна выполняться в подготовленной отдельной среде.
Smoke проверяет все четыре компонента SMC, JSON и контракт MT5 binding
(на Windows импортируется binding, но терминал не инициализируется).
`windows_vendor_smoke_verified` требует успешного smoke с точными версиями
на Windows; `windows_release_verified` всегда false, поскольку тест не
проверяет настоящий терминал. Workflow `Optional analysis Windows smoke`
сохраняется. Удаление модулей не является новым подтверждением совместимости
Windows DLL, текущих wheels, живого MT5 или готовности к реальным сделкам.

Офлайн-тесты покрывают source/history/time, ограничение и изоляцию worker,
независимые глубины кэша, компоненты SMC, отсутствие импортов удалённых
модулей и безопасные сообщения ошибок. Проверки с fake движками не заменяют
smoke настоящей библиотеки и отдельную разрешённую read-only проверку MT5.
