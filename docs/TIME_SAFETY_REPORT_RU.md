# Новая реализация защиты времени — 20 октября 2026

База: `328706563672d6f88fa26677562217d30d50a032` (work).
Это новая реализация согласованных требований. Старый неопубликованный коммит и
патч не применялись; идентичность прежней реализации не заявляется.
После восстановления среды исходное дерево было чистым. Пользовательские изменения
не удалялись. Новые стратегии и веб-интерфейс не добавлялись.

## Изменения

- `tradfi/time_safety.py`: три последовательных публичных HTTPS-измерения
  `https://api.bybit.com/v5/market/time`, без API-ключей. Таймауты подключения/чтения
  по 2 секунды, редиректы запрещены. Проверяются ответ, RTT (до 2 секунд),
  неопределённость (RTT/2 + округление), согласованность трёх интервалов,
  отклонение локального UTC вместе с неопределённостью (до 2 секунд),
  свежесть (60 секунд), скачки wall-clock относительно monotonic (1 секунда).
  Неуспешное обновление отменяет пригодность предыдущего измерения.
- `tradfi/engine.py`: отдельный durable `time_block` в SQLite. Он переживает
  рестарт; `/start` и успешная периодическая проверка его не снимают.
  `/resume_time` выполняет новые измерения и снимает только блок времени, только
  при успешных проверках, не сбрасывая MANUAL, stop, расчёты и сроки.
  Проверки повторяются при создании входа и непосредственно перед отправкой.
  Блок времени запрещает STOP/MARKET, сохраняя разрешённые существующими
  проверками OCO-отмену и сопровождение защиты активной позиции.
- `tradfi/evidence_broker.py`: native-профиль по умолчанию получает причину
  `MT5_TIMESTAMP_SEMANTICS_UNVERIFIED`. MT5 tick не является независимым UTC-эталоном.
  Непроверенные timestamps доступны в `mt5_display_time`, а не как UTC:
  quote.utc_time=None, candle.id=0. История по-прежнему не объявляется проверенной.
- Ветка хранит `branch_started_at_utc`, `branch_started_date_utc` и
  `branch_deadline_utc`. После убытка SL начинается новая ветка с новым 24-часовым
  сроком, при этом первоначальное начало цикла сохраняется. Частичный TP и
  прибыльный stepped-SL продолжают тот же срок. Рестарт его не продлевает.
  Для старого состояния без полей ветки используется исходный сохранённый срок,
  новый срок от момента рестарта не создаётся.
- По истечении срока новые входы отменяются локально до отправки; подтверждённые
  собственные pending-ордера получают CANCEL с проверкой владения и журналом.
  UNKNOWN-отмена не повторяется. Активные broker SL/TP сохраняются, принудительного
  закрытия нет. Ветка остаётся MANUAL. Исправлен повторный учёт уже закрытого
  раунда при истечении срока после частичного TP.
- `tradfi/runtime.py`, `tradfi/telegram.py`: обновление внешней проверки каждые
  30 секунд в execution loop и команда `/resume_time`. Часы ОС не меняются.
- `tools/run_offline_tests.py`: полный unittest-набор с запретом DNS и реальных
  socket connect/connect_ex. Даже перехваченная кодом попытка сети делает прогон
  неуспешным. MT5, HTTP и Telegram в тестах заменены doubles.

## Ограничения

- Реальный MT5, торговый сервис, Windows/VPS и реальные сделки не запускались.
  Фактическая доступность публичного Bybit HTTPS из VPS не проверялась.
- Семантика MT5 в production НЕ подтверждена. Поэтому по умолчанию новые входы
  остаются заблокированы даже после успешного HTTPS-измерения. Конфигурационного
  флага обхода нет; положительный verifier используется только явно в offline
  fixtures. Необходимая независимая проверка реального брокера вне этого задания.
- Отмена pending требует доступного API, подтверждённого владения и допустимого
  брокером запроса. При UNKNOWN/ошибке она не объявляется исполненной и не
  повторяется вслепую. Существующие проверки котировки, счёта и reconcile сохранены.
- Никаких push, публикации среды или изменения системных часов. Готовность к
  реальному запуску не заявляется.
