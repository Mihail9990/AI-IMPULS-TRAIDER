# Проверить запуск без команд

Полный новый архив проекта → `START_INSTALLER.bat` → **Диагностика запуска**.
Если READ_ONLY ещё работает, сначала остановите его кнопкой установщика и дождитесь завершения.
Кнопка запускает отдельную проверку в фоне, не торговый сервис. По завершении открывается Блокнот.
Максимальное время дочерней проверки — 40 секунд, MT5 initialize — 10 секунд.

Отчёт: `%LOCALAPPDATA%\AI_IMPULS_TRADFI_Manager\data\startup-diagnostic.txt`.
Файл кодируется UTF-8 с BOM для Windows Блокнота. Последняя диагностика заменяет этот небольшой отчёт;
основные торговые логи не удаляются. При неудачном открытии Блокнота путь показан в установщике.

Проверяется JSON/поля конфигурации, наличие terminal64.exe, политика пароля, профиль времени,
свободный loopback порт, подключение MT5, совпадение каталога/счёта/сервера, валюта UST,
наличие видимого XAUUSD.s, котировка и два последних M1 времени.
Валюта/режим проверяются по действующим требованиям бота; диагностика не переключает счёт.
Неизвестный режим счёта не делает реальную торговлю разрешённой.

Файлы конфигурации и базы не изменяются. Проба не создаёт Store/контроллер, не читает и не меняет
ордера/позиции, не вызывает order_send/login/symbol_select и не включает execute. Используются
initialize/shutdown и чтение terminal/account/symbol/tick/bars. Даже если в файле включено
реальное исполнение, диагностический процесс не содержит торгового маршрута. Operation/account/state
locks защищают от запуска пробы поверх сервиса; при занятости отчёт объясняет отказ.

Пароль, login счёта, серверное значение, полный terminal_path, сырой JSON, MT5 last_error и
исходный текст исключений в отчёт не попадают. Сообщения составлены из фиксированного списка
причин. Отчёт можно показать для разбора проблемы; полный service.json отправлять не нужно.
Проверка времени сравнивает SDK UTC timestamp с часами Windows, не вычитает 2/3 часа и не заменяет
независимую проверку UTC рабочего сервиса. Старая котировка или недоступные M1 дают предупреждение,
а не утверждение, что именно они вызвали прежний exit 2. Диагностика не изменяет часы, HTTPS или firewall.

Новая версия runtime дополнительно сохраняет безопасный код перехваченной ранней ошибки в
`data\startup-error.txt` (рядом с service.json). Кнопка включает только распознанный код прошлого
отказа в отчёт, отдельно отмечая его как прошлый. Неизвестные ошибки остаются STARTUP_UNKNOWN:
сырой exception с потенциальными секретами не раскрывается. При отказе записи файла безопасное
сообщение остаётся в stderr; установщик прежних версий его глушит.

Для самой кнопки нужен новый полный архив, где рядом с install_tradfi.py находятся
startup_diagnostics.py и пакет tradfi. Проверка может использовать venv уже установленного f739040;
обновлять сервис ради пробы не обязательно. Для сохранения startup-error.txt самим рабочим runtime
нужно установить новую опубликованную версию кнопкой «Установить / обновить». До публикации
не нажимайте обновление в расчёте получить этот ещё локальный коммит.

Проверка не анализирует SQLite, активный цикл, историю сделок и все ограничения торгового символа.
Даже отчёт без ERROR не означает готовность реальной торговли. Восстановление старого потерянного
stderr невозможно; проверка получает новые read-only наблюдения.

Здесь проверено на fake MT5 и offline тестах. Реальные Windows/MT5/Блокнот на VPS не запускались.
